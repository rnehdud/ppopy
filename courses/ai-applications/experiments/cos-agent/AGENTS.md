- 앱 입력의 미상·거절·사용자 확인·제품 버전 의미를 보존한다.

- 현재 위치/핵심 결과/한계를 갱신하고 새 E번호로 목적·변경·조건·실제 검사와 결과·해석·반례·다음 작업·증빙 경로를 덧붙인다. 문서 끝의 양식을 사용한다.
- `docs/afa-policy-evidence.json`에도 같은 E번호의 핵심 수치, 원본 보고서 경로·SHA-256, 출처 유형을 추가한다. 과거 기록·receipt를 새 결과로 덮어쓰지 않는다. 정정은 날짜·사유·영향과 새 증빙을 남긴다.
- 소프트웨어 검사, 학습 연결 점검, 정책 비교, 독립 평가를 구분한다. 고유 상황/가족과 반복 수, train/확인 역할, 미실행 검사, 규칙 복구·실패·부분군 악화를 함께 기록한다.
- 원본 JSON/CSV/stdout과 명령·종료 코드는 새 `outputs/` 경로에 보관하고, 공유 가능한 수치·해시는 문서에 남긴다. outputs가 Git에서 제외되므로 발표용 원본 보관·재현 경로를 명시한다. 개인 정보·비밀·가중치·원시 외부 자료를 문서에 복사하지 않는다.
- 발표에서 PPO 우위·임상 정확도·미노출 최종 test·v67 학습을 실제 근거 없이 주장하지 않는다. 초기 소스 버전/로그가 보존되지 않은 경우도 밝힌다.
- 새 용어·호출·설정은 처음 나올 때 쉬운 뜻, 실제 값, 사용하는 이유와 한계를 설명한다. 결과에는 분모와 좋은 방향을 적고, 가상 설명 예시와 실제 측정을 구분한다. 발표용 전체 흐름을 먼저 보여주고 재현용 기술 상세는 별도 절에 보존한다.

## Linear 결과 이미지

2026-11-18: 결과가 있는 단계는 실제 MLflow 화면과 핵심 해석·한계를 진행 문서에 함께 남긴다. Linear 본문에는 로컬 경로 대신 직접 업로드한 asset URL로 이미지를 표시한다. `docs/afa-linear-assets.json`의 로컬 경로·SHA-256이 맞을 때만 URL을 재사용하고, 이미지가 바뀌면 새로 업로드해 대응표를 갱신한다. 동기화 전 원격 이미지 URL을 대응표의 로컬 경로로 되돌려 원본과 비교하고, 저장할 때 다시 URL로 렌더링한다. 원본 문서 해시는 로컬 Markdown 기준으로 유지한다. 기록 없는 단계의 결과 화면을 만들지 않으며 그래프 원본과 창 캡처를 구분한다. 캡처·import 시간/소요시간을 원본 학습 시간으로 표현하지 않는다.
