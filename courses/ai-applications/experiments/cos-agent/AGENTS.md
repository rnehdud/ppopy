# 이 작업 공간의 개발 원칙

## 현재 사용자 지시

2026-11-06: 모든 커밋과 푸시는 작업별 별도 브랜치에서 진행한다. main에 직접 커밋·푸시·병합하지 않는다. main 병합 여부는 개발자가 직접 판단한다.

2026-11-02: 지금은 전체적인 가이드라인과 프로젝트 개발 틀에 집중한다. 한 번에 다 구현하지 않고 점진적으로 발전시킨다.

- 먼저 `docs/project-guide.md`를 읽고 현재 요청의 범위를 확인한다.
- 설계 요청을 대규모 기능 구현으로 확대하지 않는다. 단계별로 작은 결과물을 만든다.
- 이미 있는 `beauty_agent/`는 합성 실험 골격이다. 최종 구조·모델·런타임 선택으로 취급하지 않는다.
- 사용자가 정한 목표, 확인된 사실, 제안, 미결정을 문서에서 구분한다.
- 기존 SkinAnalysis 앱과 Linear BeautyLIFE는 참고 자료다. 원격 규칙을 이 독립 작업 공간의 확정 요구사항으로 무조건 복사하지 않는다.
- 앱 입력의 미상·거절·사용자 확인·제품 버전 의미를 보존한다.
- 모델은 교체 가능하게 두고 제품 사실·권한·승인 검사를 코드와 데이터로 관리한다.
- 실제 앱 연동·모델 실행·사람 검토를 하지 않았다면 완료했다고 기록하지 않는다.
- 요청 범위에 필요한 검사만 수행하고 확인된 한계를 설명한다.
