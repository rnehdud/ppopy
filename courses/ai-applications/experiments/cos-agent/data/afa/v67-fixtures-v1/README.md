# v67에서 파생한 작은 응답 자료 — E22

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

목적은 **정책이 질문 순서를 바꾸더라도 정의된 응답을 받게 하는 것**이다. PPO 학습·Gym 연결·최종 판단의 정답을 제공하는 단계는 아니다. 상세와 실제 결과 화면은 [응답 계약 설명서의 E22 절](../../../docs/afa-v67-response-contract.md#e22-fixtures)을 본다.

## 무엇이 들어 있나?

| 파일 | 역할 |
| --- | --- |
| [design.json](design.json) | 범위, 부모 train 시나리오 4개, 추가할 가상 값과 미지원 기능 |
| [fixtures.jsonl](fixtures.jsonl) | 부모 계보·초기 공개 정보·환경만 아는 응답표·응답 출처 |
| [responses.jsonl](responses.jsonl) | 상황 ID와 공개 이력·행동·대상·확인 초점으로 찾는 응답 연결 60개 |
| [derived-labels.jsonl](derived-labels.jsonl) | 919 첫 턴만 조건부로 수정한 별도 라벨 1개. 현재 학습에는 연결 안 됨 |
| [manifest.json](manifest.json) | 자료·원본·설계·생성 코드의 해시와 실제 집계 |

부모는 train-847/848/849/851이며 모두 B-C02(도구·마찰·건조) 상황이다. 각 상황은 처음에 얼굴 사용만 공개하고 나머지 3개 답은 환경에 둔다. 기록된 미상 3개·거절 1개를 보존하고, 나머지 8개 답은 **새로 작성한 가상 설정**으로 명시했다. 원래 값이 있다고 순서를 바꾼 질문에도 같은 답을 한다는 것은 명시적인 정적 실험 가정이다. 원래 후속 문장과 다음 질문 요청을 다른 경로에 재생하지 않는다.

한 상황의 질문 순서는 `3 × 2 × 1 = 6`개다. 4상황 × 6 = **24개 순서**이며 사용자·독립 상황 24개가 아니다. 각 순서의 중간 이력까지 검사하면 **공개 이력 64개, 응답 연결 60개**가 된다. 이는 KB가 허용할 실제 질문 경로보다 넓은 자료 수준 검사다. 이 자료가 질문을 실행할 권한을 주거나 KB의 종료·억제 분기를 바꾸지 않는다.

## 재현

실험 폴더에서:

```powershell
uv run --locked python -m beauty_agent.afa.v67_fixtures verify --report ../../../../outputs/afa-fixture-check-new.json
uv run --locked pytest -q tests/afa/core/test_v67_fixtures.py
```

처음 생성하는 새 버전에서는 `build`를 사용한다. 이미 있는 자료를 덮어쓰지 않는다. 버전을 수정할 때는 별도 디렉토리·설계·계보를 갖춘 새 버전으로 만든다. 정정·충돌·제품/프로필 갱신·후보 확인·조회가 있는 부모는 이 정적 응답 생성 범위에서 거부한다.

`ResponseBook`은 응답 하나라도 없거나 바뀌면 초기 검증에서 실패한다. 미등록 경로·다른 이력·재질문·다른 행동은 답을 지어내지 않고 오류를 낸다. 실제 unknown/거절 응답은 그대로 반환한다. 행동 실행·상태 저장·보상·Gym 전이는 하지 않는다.
