# AFA benchmark v2 — 확장 전 요구사항과 결정 순서

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

상태: **의미 계약의 첫 기술 버전·실행 검사가 추가됐으며, 실행 가능한 v2 데이터/Gym 환경은 아직 없음.** [의미·응답·중단 계약](../semantic-v2-v1/README.md)은 기존 첫 매칭 의미를 보존하고 공개 정보로 결과 확정 여부를 검사한다. 독립 도메인 검토는 미완료다. 원본 KB·v67·v1 fixture는 보존한다. 여기서의 설계값은 사용자 효용·전문가 정답·제품 사실이 아니다.

2026-11-17: [첫 확장 연습장 설계](../scenario-plan-v2-v1/README.md)를 추가했다. 첫 버전은 C01+C02 공동 검토 48개 known-answer 설계, 별도 모름/거절/정정 등 점검 예시 9개, 비용 2조건, 16가족의 내부 30/9/9 분할이다. 실행용 응답 자료·adapter·Gym 환경·본 비교 protocol은 아직 없다. 아래 로드맵 전체를 완료한 것으로 해석하지 않는다.

## 숲: 두 가지 질문을 따로 평가한다

1. **질문 순서:** 같은 판정·안전 수준을 유지하면서 적은 비용으로 필요한 정보를 얻는가?
2. **정보 획득과 중단:** 선택 정보의 추가 획득 가치가 비용보다 작은 때 적절히 멈추는가?

v1은 첫 질문의 작은 기술 실험이다. 모든 답이 known이고 최대 4회면 완결되며 잘못된 종료 손실이 전체 질문 비용보다 크다. 이 설정만으로 불확실성 아래의 중단 최적화가 검증되지는 않는다. 두 과제를 다른 cohort/metric으로 정의하고, 안전상 필수 질문을 생략하는 정책을 성능 개선으로 보지 않는다.

## 나무: 입력 → 작업 → 산출물 → 통과 조건

## 의미 계약에서 검토해야 할 구체적 사례

- 도구와 마찰이 모두 difference인 세계: 먼저 물은 슬롯에 따라 다른 action이 나오는데 두 결과가 정말 대체 가능한가?
- 여러 카드 중 하나가 안전 보류를 내면 다른 질문을 모두 닫아야 하는가? 필수 안전 정보를 확인하지 못했을 때의 보류는 어떤 의미인가?
- unknown/declined 뒤 재질문·다른 질문·보류 중 무엇이 가능한가? 모름과 안전상 문제가 없음을 구분하는가?
- 선택 정보를 얻지 않고 초안을 낼 수 있는 조건은 무엇인가? 초안 제공률을 낮춰 비용만 줄이는 것을 어떻게 막는가?
- 제품 근거 조회 실패는 사용자 응답 결측과 어떻게 구분하는가? 사용자 확인이 제품 사실을 승인하는 것으로 변환되지 않는가?

각 결정에는 예시 입력, 허용/금지 행동, 예상 권고·보류, 검토 상태를 붙인다. 해결 전에는 새 reference를 승인하거나 해당 세계를 학습에 섞지 않는다. 원본 KB를 바꾸는 선택은 별도의 버전·기록·검증을 요구한다.

## 완료의 의미

현재 완료한 것은 **진단 코드·의미 충돌 증거·확장 요구사항**이다. 이 문서가 존재해도 v2 구현이나 독립 평가 준비가 완료되는 것은 아니다. Stage 5A의 학습 연결은 v1에서 진행할 수 있지만 성능 우위 주장은 위 조건을 만족한 후 별도 평가한다. 실제 앱 연결·사용자 수집·제품 승인·자동 개선 판단은 활성화하지 않는다.
