# AFA Stage 0 v1 — 첫 실험의 범위와 성공 기준

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

기준: [PPO-23](https://linear.app/ppopy/issue/PPO-23)의 Stage 0. 이 묶음은 **실험 명세와 기계적 검사**다. RL 환경·학습기·정책·독립 평가셋은 아직 없다. `development_preview`, `production_enabled=false`를 유지한다.

## 왜 이 작업을 하는가?

전체 순서는 **범위/성공 기준 → 응답 자료 → 환경 → 기준선 → RL → 평가 → 연결/확장**이다. 지금은 첫 단계다. 모델 학습 전에 다음을 고정해야, 질문을 잘 골라 비용이 줄었는지 또는 항상 보류하는 편법인지 구분할 수 있다.

| 산출물 | 목적 |
| --- | --- |
| `contract.json` | 범위·고정 행동 번호·숫자 상태 schema·설계 비용·종료 의미 고정 |
| `examples.synthetic.json` | 사람이 작성한 작은 경로의 예상 질문·종료·return 명시 |
| `beauty_agent/afa/stage0.py` | 기존 KB와 게이트에서 그 계약이 성립하는지 검사 |
| 루트 `outputs/afa-stage0/report.json` | 합성 세계·질문 순서·참조 차이·제외 사유를 추적 |

## 첫 범위

- B-C01(물 온도): 단일 슬롯과 올바른 보류의 기본 검사.
- B-C02(도구·마찰·건조): 같은 세계에서 질문 순서가 달라도 허용 결과를 유지하는지 검사.
- 한 사례는 카드 하나만 선택한다. 프로필과 기존 가상 `demo-cleanser/fixture-v1`은 확인된 합성 입력이다. 실제 제품 사실이나 사용자 기록이 아니다.
- 처음 공개된 관찰은 비어 있다. 숨겨진 합성 세계의 부위는 face이며, 먼저 물어 확인해야 세부 질문이 열린다.
- 자연어 추출·후보/정정·제품 근거·다중 카드·실사용·학습은 범위 밖이다. 모든 미상/거절/충돌에 대한 일반 환경을 구현한 것이 아니다.

전체 여섯 액션 계약을 축소/변경하지 않는다. 이번 연구 과제만 `ask_user`, `hold`, `request_draft`로 제한한다. 고정 8개 쌍은 질문 5개 + hold 대상 2개 + 초안 대상 1개다. 최종 마스크는 **과제 지원 쌍 ∩ 기존 런타임 enabled 쌍 ∩ 예산 조건**이다.

주의: 부위만 알려진 상태에서 원래 Context에 제품 조회 요청도 보일 수 있다. 이것을 해결된 근거로 바꾸지 않는다. 조회는 이번 연구의 선택 범위 밖이며, 지원되는 모든 질문 경로가 제품 사실 없이 full-current 결과에 도달하는 세계만 남긴다. 이후 일반화할 때 별도 근거 입력 계약이 필요하다.

## 참조와 모호 사례

참조는 **이 합성 세계의 현재 모든 답을 기존 엔진에 제공한 기계적 결과**다. 의학적 진실·사람 정답·사용자 적합성 승인이 아니다. `human_review=unreviewed`, `approved_reference=false`, `training_ready=false`다. v67에서 뽑은 사례가 아니라 새 설계 격자이므로 v67 계보/분할을 주장하지 않는다.

비교 필드: 카드 ID, comparison_status, 정렬한 action_types, recommendation_text, hold_signals, overall, 초안 가능 여부. branch ID와 reason 문자열은 정답 조건에서 제외한다. 안전 의미는 action/hold에 유지한다. **새 의미 동등성 라벨은 만들지 않는다.**

B-C02의 도구 차이는 `inform_general_practice`, 마찰/건조 차이는 `suggest_behavior_change`다. 둘이 함께 있는 숨겨진 세계는 질문 순서에 따라 서로 다른 행동으로 끝날 수 있다. 이 버전은 어느 쪽이 도메인 정답인지 임의로 승인하지 않고 **그 세계 전체를 제외**한다. 이후 별도 의미 계약으로 재검토한다.

정적 격자 19개: B-C01 3개, B-C02 16개. 지원 질문 순서를 기계적으로 모두 검사했을 때 B-C01 3개/B-C02 7개가 의미 서명을 유지하고, B-C02 혼합 의미 세계 9개를 제외한다. 이 숫자는 연구 데이터셋 규모·성능·독립성 지표가 아니다. 제공 명령으로 재현한다.

## 비용·종료 설정 — 모두 합성 설계값

| 항목 | v1 설정 / 이유 |
| --- | --- |
| 질문 비용 | 1 단위. 실제 시간·피로 측정값이 아님 |
| 질문 예산 | 최대 4회: 부위 + B-C02의 세 슬롯을 모두 물을 수 있음 |
| 잘못된 종료 손실 | 5 = 최대 획득 비용 4 + 1. 즉시 잘못 보류가 유효한 완전 경로보다 유리하지 않게 함 |
| 올바른 종료 손실 | 0. 질문 비용은 그대로 남음 |
| gamma / shaping | 1.0 / 0. 총비용 목적과 맞춤 |
| return | `-질문수 - 종료손실` |
| 품질 허용 오차 | 기계적 서명 불일치 0, 게이트 위반 허용 0 |

이는 최종 보상 보정/사용자 효용값이 아니다. 비용 민감도·최소 비용 개선폭·통계적 기준은 기준선 단계에서 모델 선택 전에 정한다. 현재 그 성능 주장 임계값은 null이며 우월성 평가를 승인하지 않는다.

- **올바른 초안:** 게이트가 허용하고 현재 서명이 full-current 참조와 일치하며 full-current도 초안 가능.
- **올바른 보류:** full-current가 보류이고 현재 서명이 일치하며 지원 질문이 더 없음. 예: B-C01의 cold 응답은 엔진에서 미해결 상태로 남는다.
- **성급한 보류:** 런타임이 hold를 허용해도 위 조건을 만족하지 않으면 손실 5.
- **부적절한 초안/invalid action:** 실행 게이트의 hard error. 임의의 정상 transition으로 보상하지 않는다.
- **예산 소진:** 마지막 질문 뒤 유효한 무료 종료를 허용한다. 아직 해결되지 않은 과제 예산 종료에는 손실 5. 외부 truncation/bootstrap 구현은 Stage 2~3의 별도 계약이다.

## 예상 사례로 이해하기

| 사례 | 질문 경로 | 종료 / return |
| --- | --- | --- |
| 미온수 | 부위 → 물 온도 | 합성 초안 / -2 |
| 찬물 | 부위 → 물 온도 | 정당한 보류 / -2 |
| 도구 차이만 있음 | 부위 → 도구 | 합성 초안 / -2 |
| 손 사용·강한 마찰 | 부위 → 마찰 | 합성 초안 / -2 |
| 같은 마찰 차이를 늦게 질문 | 부위 → 도구 → 건조 → 마찰 | 합성 초안 / -4 |
| 손·부드러운 마찰·가볍게 건조 | 부위 → 도구 → 건조 → 마찰 | 합성 초안 / -4 |
| 정보 없이 즉시 hold | 질문 없음 | 성급한 보류 / -5 |
| 도구 차이와 마찰 차이가 함께 있음 | 경로별 action_types 다름 | v1 참조에서 제외 |

초안은 기존 합성 표시 사용법 배열이다. KB 안내를 임상적 개인화 루틴으로 변환하지 않는다.

## 상태 schema와 공개 경계

숫자 인코더는 **명세만 존재**하며 Stage 2에서 구현한다. 슬롯 5개의 상태 one-hot(6상태), 값 one-hot(미관찰 null 포함), task 2개, action mask 8개, 잔여 예산으로 58차원을 정의했다. first-world 값과 참조·ID는 정책에 주지 않는다. null은 측정값이나 부정이 아니다. 미질문·모름·거절·미해당·충돌·known 상태는 구분한다. 지금 격자는 known 응답만 다룬다.

검사기는 질문 순서를 열거해 명세를 검사할 뿐 Gym reset/step, Session commit, 실제 정책용 관찰 인코더를 제공하지 않는다. stage0 검사 보고서의 숨겨진 답·참조는 정책 입력이 아니다.

## 실행 / 검증

실험 폴더(`cos-agent/`)에서:

```powershell
uv run python -m beauty_agent.afa.stage0 --report ../../../../outputs/afa-stage0/report.json
uv run pytest -q tests/test_afa_stage0.py
```

보고서는 루트 outputs 아래로만 쓴다. source_hashes는 현재 엔진/규칙/게이트/카탈로그의 실험 결합 버전이다. 기존 원본 manifest를 갱신하거나 실패를 감추려고 pin을 바꾸지 않는다. 엔진 변경 시 별도 실험 버전으로 재검토한다.

## 다음 단계

Stage 0의 **기술 명세·기계적 검사**를 만든 상태다. 도메인/사람 검토나 학습 준비 완료가 아니다. Stage 1에서 v67 지원 검사와 파생 사례 계보·분할을 정의하고, Stage 2에서 prepare_context/apply_action과 인코더를 구현한다. 원본 KB·57개 감사·기존 다섯 실패·런타임 동작·의존성은 변경하지 않는다.

KB coverage·합성 CLI도 실행했다. 엄격 원본은 62개 통과/기존 5개 실패(T17, T20, T37, T45, V06-T04), 원본 감사는 52/57이며 두 명령의 종료 코드 1을 보존한다. 이 검사는 학습 성능·독립 정답·원본 수용 완료가 아니다.
