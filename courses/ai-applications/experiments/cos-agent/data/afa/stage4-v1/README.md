# AFA Stage 4 — RL이 비교할 기준선

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

목적: **검증된 환경에서 기존 방식의 질문 비용·판정·보류를 측정한다.** 이후 RL이 무작위 방식만 이긴 것을 개선으로 부르지 않고, 같은 품질과 제공 수준을 유지하는 가장 강한 기준선과 비교하기 위함이다. 이번 단계는 RL/PPO 학습을 실행하지 않는다.

## 동일 비교 조건

- Stage 0의 과제·비용·손실·게이트와 Stage 1의 고정 세계를 그대로 사용한다.
- 모든 정책의 `select` 입력은 **58차원 공개 관찰과 8개 행동 마스크**뿐이다. 실제 평가 세계의 ID·전체 답·참조·정답은 넘기지 않는다.
- 분포/BC fitting은 train 6개 세계만 사용한다. 평가는 train과 val_internal 2개, seed 0/1/2로 수행한다. **Stage 4 runner는 test_internal 성능 측정을 거부한다.**
- 숨겨진 세계의 답변은 환경이 선택한 질문에 대해서만 공개한다. evaluator의 참조 계산과 하한 분석은 정책 입력/학습과 분리한다.
- 실행 조건과 metric 정의는 `protocol.json`에 기록한다. 전체 조건/코드·프로토콜 해시와 BC 표는 루트 보고서에 남긴다. 설정 탐색이나 val 결과에 맞춘 정책 재학습은 수행하지 않았다.

## 다섯 기준선의 의미

| 이름 | 선택 방법 | 알아둘 한계 |
| --- | --- | --- |
| 기존 규칙 순서 | 질문 우선, 그다음 초안, 마지막 보류. 질문 동률은 현재 Context와 같은 타깃 순서 | 정적 과제 범위에서 기존 RuleBasedActionPlanner와 선택 일치를 검사 |
| 전체 허용 행동 무작위 | 현재 enabled 행동 중 균등 선택 | 중간 hold도 고르므로 질문이 적어도 품질은 낮을 수 있음 |
| 질문만 무작위 + 고정 종료 | 질문이 있으면 질문 중 무작위, 없으면 규칙의 종료 선택 | 질문 순서 효과를 보류 선택 효과와 분리 |
| train 분포 기반 탐욕 + 고정 종료 | 현재 공개 답과 일치하는 train 세계의 경험 분포로 다음 질문의 1단계 종료손실 감소/비용을 계산 | 실제 평가 세계의 숨겨진 답은 모름. 장기 최적 VOI/중단 정책이 아님 |
| 표 기반 BC | train의 고유 공개 상태 28개에서 기존 규칙의 행동을 저장해 모방 | 경량 지도 빈도/lookup 기준선. 신경망·Qwen SFT가 아니며 새 상태는 규칙으로 복구 |

탐욕 방식은 **질문 사이의 선택만** 최적화하고 종료는 기존 게이트 기반 규칙을 사용한다. 더 나은 다단계 질문 조합이나 종료 판단을 학습한 것으로 표현하지 않는다. train 분포에 해당 상태의 지지가 없으면 규칙으로 복구하고 횟수를 센다.

BC 목표는 규칙 교사가 만든 합성 기술 라벨이다. 사람/전문가/최적 행동 정답이 아니다. 같은 공개 상태는 질문 순서·세계가 달라도 한 샘플로 중복 제거한다. 새 상태에서의 규칙 복구와 모델이 실제 기억한 선택을 구분해 기록한다.

## 측정 결과 — 작은 내부 개발 자료

평균 질문 수와 **정의한 종료 계약 충족률**을 함께 표시한다. 임상 정확도나 실사용 성능이 아니다. 세 seed를 반복해도 고유 세계는 train 6개/val 2개이며, 결정론적 정책 반복을 독립 표본으로 보지 않는다.

| 방식 | train 평균 질문 | train 종료 계약 충족률 | val 평균 질문 | val 종료 계약 충족률 |
| --- | ---: | ---: | ---: | ---: |
| 기존 규칙 | 3.333 | 1.000 | 2.000 | 1.000 |
| 전체 허용 행동 무작위 | 0.889 | 0.000 | 0.833 | 0.167 |
| 질문만 무작위 | 2.944 | 1.000 | 2.167 | 1.000 |
| train 분포 탐욕 | 2.500 | 1.000 | 2.500 | 1.000 |
| 표 기반 BC + 규칙 복구 | 3.333 | 1.000 | 2.000 | 1.000 |

BC는 train에서 복구 0회, val의 6회 episode(2세계×3seed) 동안 복구 3회였다. val 결과를 순수 BC의 독립 일반화로 해석하지 않는다. 전체 무작위는 질문이 적지만 성급한 hold 때문에 종료 계약 충족률이 낮다. 질문 비용만 보고 이 정책을 가장 좋다고 고르면 안 된다.

보고서에는 카드별·seed별 평균/중앙값/p95 질문·cost/return·초안/보류율·잘못된 보류·의미 일치·복구 수·각 episode trace가 있다. 초안 제공 0건이면 조건부 초안 오류율은 null이며 0으로 표현하지 않는다. 정책 선택 또는 환경이 오류를 내면 비교를 중단한다. 완료된 보고서의 runtime reject/fallback 0은 실패를 숨긴 값이 아니다.

## 중요한 결론: 현재 val에서는 질문 비용 개선 여지가 없다

품질을 유지한 기준선 중 train에서는 탐욕(평균 2.5), val에서는 규칙/BC(평균 2.0)가 가장 적은 질문을 사용했다. 따라서 RL은 무작위나 약한 한 방식만이 아니라 이 수준과 비교해야 한다.

evaluator가 숨겨진 답을 알고 계산한 세계별 최선 경로의 평균 비용 하한은 train 2.333, val 2.000이다. **현재 val에서는 기존 규칙이 이미 이 하한에 도달했다.** 같은 종료 품질을 유지하며 평균 질문 수를 2보다 낮추는 목표는 이 고정 val 과제에서 불가능하다.

train의 2.5→2.333 차이도 실제 정책이 달성 가능하다는 보장은 없다. 하한은 세계마다 숨겨진 답을 보고 다른 최선 질문을 선택하는 hindsight 분석이다. 동일 공개 상태에서 그 세계를 알아맞힐 수 있는 정책을 의미하지 않는다.

Stage 5에서 이 자료로 학습/연결 기술 점검은 할 수 있다. 그러나 질문 비용 우위를 연구하려면 **현재 결과를 보존한 채 별도의 더 넓은 과제·응답 세계·사전 평가 계획**을 먼저 설계해야 한다. RL에 유리한 결과를 얻으려고 기존 val/test를 조용히 다시 고르지 않는다. 현재 작은 자료의 결과로 통계적/외부 일반화 우위를 주장하지 않는다.

## 실행과 산출물

`cos-agent/`에서:

```powershell
uv run --group rl python -m beauty_agent.afa.baselines --report ../../../../outputs/afa-stage4/baselines.json
uv run --group rl pytest -q tests rl_tests
```

- 구현: `beauty_agent/afa/baselines.py`
- 고정 절차/지표: 이 폴더 `protocol.json`
- 결과·BC 학습 표·코드/설정 해시·공개 행동 trace: 루트 `outputs/afa-stage4/baselines.json`
- 검사는 규칙 선택 일치, train-only fitting, 동일 공개 입력, unseen 상태 복구, 무작위 재현, test scoring 거부, 분할별 동일 세계 비교를 다룬다.

`future_rl_comparison`은 동일 품질/coverage에서 비용을 엄격히 줄이는 합성 설계 기준이다. 실제 임상/사람 검토 승인이 아니다. 파이프라인은 계속 `development_preview`, `production_enabled=false`이며 원본 엔진·KB·v67·Stage 0/1 분할은 변경하지 않았다.

## 실행 확인 — 2026-11-16

train/val × 5정책 × 3seed로 120회 episode를 실행했다. 고유 세계는 8개이며 120개 독립 사례가 아니다. BC는 train의 공개 상태 28개를 저장했고 test scoring은 수행하지 않았다. 결과·학습 표·프로토콜과 코드 해시는 outputs/afa-stage4/baselines.json에 있다.

신규 기준선 검사 9개, 전체 실험/rl 검사 351개 통과. 기존 Starlette/httpx 경고 1건. 원본 manifest 27/27, KB 구조 95/95, 경계·현재 명세 371개 통과. coverage·합성 CLI 실행. 엄격 원본은 기존 62 통과/5 실패, 원본 감사는 52/57 및 종료 코드 1을 유지했다.
