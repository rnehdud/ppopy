# 기존 질문 방식 비교 — PPO가 넘어야 할 기준

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

**비교를 마쳤습니다. 질문 순서를 잘 고르면 덜 물을 수 있지만, 현재 연습장에서는 미리 계산하는 방식이 이미 최선에 도달했습니다.** 이번에는 PPO를 학습하지 않았습니다.

## 가장 중요한 결과부터

내부 확인용 가상 상황 9개에서, 질문 비용을 모두 1로 계산했습니다.

| 방식 | 평균 질문 수 | 정해둔 종료 기준 충족 |
| --- | ---: | ---: |
| 기존 실행 코드의 질문 순서 | 4.67회 | 9개 모두 |
| 질문 순서만 무작위 | 3.78회 | 9개 모두 |
| 바로 다음 질문의 효과만 계산 | 4.67회 | 9개 모두 |
| 여러 질문의 순서를 미리 계산 | **3.00회** | **9개 모두** |
| 질문·보류를 모두 무작위로 선택 | 1.33회 | 평균 14.8% |

무작위 보류 방식은 빨리 끝내지만 대부분 성급한 보류였습니다. 질문 수만 적다고 좋은 방식이 되는 것은 아닙니다. 위 충족률은 기존 엔진 기반의 합성 종료 계약이며 실제 사용자 만족·임상 정확도가 아닙니다. 무작위 행은 seed 3개를 합친 평균입니다.

**미리 계산하는 방식은 사용자 답을 미리 본 것이 아닙니다.** 학습용 가상 상황 30개에서 답의 분포를 집계하고, 현재까지 받은 답만으로 다음 질문을 선택합니다. 어떤 답이 오느냐에 따라 이후 질문을 어떻게 고를지도 계산합니다. 실제 내부 확인 상황의 전체 답·ID는 선택 함수에 넘기지 않습니다.

## 왜 이 결과가 중요한가?

단순한 기존 순서보다 평균 약 1.67회 덜 물을 수 있었습니다. 그러나 더 강한 계산 방식이 이미 3회에 도달했으므로, PPO를 기존 순서와만 비교해 좋아졌다고 발표하면 불충분합니다.

별도 진단으로 공개 정보만 사용하면서 가능한 최적 질문 비용도 계산했습니다. 그 결과 현재 조건에서는 가장 강한 기존 방식과 같았습니다.

| 비용 조건 / 자료 | 가장 강한 기준선 비용 | 공개 정보로 가능한 최적 비용 |
| --- | ---: | ---: |
| 질문마다 1점 / 학습용 30개 | 3.60 | 3.60 |
| 질문마다 1점 / 내부 확인 9개 | 3.00 | 3.00 |
| 마찰·건조 2점 / 학습용 30개 | 4.20 | 4.20 |
| 마찰·건조 2점 / 내부 확인 9개 | 3.00 | 3.00 |

따라서 **현재 고정된 분포에서 동일한 품질을 유지하며 이 기준선보다 기대 질문 비용을 더 줄일 여지는 없습니다.** 이 결론은 이 작은 합성 과제와 비용·종료 규칙에 한정됩니다. 실제 사용자·더 넓은 에이전트 문제에서 PPO가 필요 없다는 결론은 아닙니다.

## 무엇을 어떻게 비교했나?

- 학습 자료: train 30개만 답 분포 추정에 사용.
- 비교 자료: train 30개와 val_internal 9개. test_internal 정책 점수는 계산하지 않음.
- 비용 조건: 기존 설계의 기본 비용과 비용 변화 조건 두 가지 그대로 사용.
- seed: 0/1/2, 설정 탐색·추가 학습 없음.
- 정책 입력: 지금까지 공개된 64차원 관찰과 현재 행동 마스크 8개뿐.
- 종료: 초안/보류의 기존 실행 조건과 v2 의미 확정 기준을 모든 방식에 동일 적용.
- 총 실행: (30+9) × 5방식 × 3seed × 2비용 = **1,170 episode**. 고유 상황은 39개이며, seed 반복을 독립 사례 증가로 세지 않음.

정정·모름·거절 예시 9개는 이전 단계의 소프트웨어 점검 자료로 남겨두고, 이번 비용·정책 점수에는 섞지 않았습니다. v67도 사용하지 않았습니다. BC/SFT 신경망과의 비교·PPO 학습·앱 연결은 수행하지 않았습니다.

**자료 구성의 한계도 확인했습니다.** 고정 가족 배정 결과, train에는 hands 12개와 세 도구 유형 각각 6개가 있지만 val_internal에는 washcloth/sponge/scrub_brush가 각각 3개이고 hands 사례는 없습니다. 따라서 이 확인 묶음은 도구 답으로 C02 의미가 빨리 고정되는 경우만 포함합니다. 3회라는 값이 모든 세안 방법의 난도를 대표하지 않습니다. 가족 분할만으로 난도 구성이 균형 잡히는 것은 아니었습니다. test_internal의 구성도 이전 개발 점검 대상이며 이번에 정책 점수는 계산하지 않았습니다.

이 결과를 보고 현재 val/test나 seed를 다시 고르지 않았습니다. 본 성능 실험에는 별도 버전에서 결과 열람 전에 난도·질문 의존성별 구성 기준과 가족 분리 조건을 함께 설계해야 합니다. PPO가 이기게 하려는 재선정이 아니라 평가 범위의 누락을 통제할 문제로 남깁니다.

### 비교한 방식의 구체적인 뜻

| 이름 | 선택 방법 | 한계 |
| --- | --- | --- |
| 기존 순서 | 현재 v2 Context에서 원본 RuleBasedActionPlanner가 고르는 행동과 같은 순서 | v2 추가 질문을 포함한 기존 실행 우선순위의 비교이며 원본 엔진만으로 그 질문이 가능하다는 뜻은 아님 |
| 질문 무작위 | 질문이 남으면 질문 중 무작위. 질문이 없으면 정당한 초안/보류 | 질문 순서 효과만 분리 |
| 바로 다음 질문 계산 | 학습 분포에서 그 질문 뒤 추가 질문이 없어질 확률 × 종료 손실 / 비용 | 장기 질문 조합이나 확률적 중단 최적화가 아님. 동률이면 저비용·질문 ID 순 |
| 여러 질문 미리 계산 | 학습 분포에 맞는 현재 상태에서 향후 답별 경로를 고려한 정확한 기대 비용 최소화 | 작은 유한 상태·알려진 KB에 맞는 계산 기준선. 학습형 신경망이 아님 |
| 전체 행동 무작위 | 현재 허용된 질문·보류·초안 중 무작위 | 낮은 비용만으로 성능을 판단하는 실수를 드러내기 위한 비교 |

학습 분포에 현재 답과 일치하는 세계가 없으면, 두 계산 방식은 기존 규칙으로 복구하고 횟수를 기록합니다. 기본 비용의 내부 확인 실행에서 바로 다음 질문 방식은 총 27회 복구했습니다(9세계 × 3seed). 그 행을 순수한 분포 모델의 독립 일반화 결과로 부르지 않습니다. 여러 질문 계산 방식은 이번 평가 경로에서 복구 0회였습니다.

### 학습용 자료 결과와 비용 변화

| 방식 | train 기본 질문/비용 | val 기본 질문/비용 | train 비용 변화 조건 | val 비용 변화 조건 |
| --- | ---: | ---: | ---: | ---: |
| 기존 순서 | 4.600 | 4.667 | 6.200 | 6.333 |
| 질문 무작위 | 4.178 | 3.778 | 5.356 | 4.556 |
| 바로 다음 질문 계산 | 4.600 | 4.667 | 4.200 | 3.000 |
| 여러 질문 미리 계산 | 3.600 | 3.000 | 4.200 | 3.000 |

위 네 방식은 모든 실행에서 종료 계약을 충족했습니다. 비용 변화 조건의 숫자는 질문 횟수가 아니라 가중 비용입니다. 비용 2는 실제 피로·시간 측정값이 아닌 미리 정한 합성 실험 조건입니다.

## 최적 비용 진단을 읽을 때 주의할 점

실제 정책은 train 답 분포만 봅니다. 최적 비용 **진단**은 평가자가 해당 train/val 분포를 알고 별도로 계산합니다. 동일한 공개 답에서는 하나의 질문을 선택하고, 다음 답이 온 후에만 경로를 나눕니다. 현재 사용자 세계 ID로 답을 미리 알아맞히는 계획은 허용하지 않습니다.

이 진단은 평가 분포를 아는 조건이므로 배포 정책·학습 결과로 사용하지 않습니다. 코드는 train 모델과 별도의 evaluator-only 경로로 분리합니다. test_internal은 이 진단에서도 거부합니다.

숨겨진 전체 답을 아는 세계별 hindsight 하한은 기본 train 3.5, 비용 변화 train 4.0입니다. 이 숫자가 더 낮다고 실제 공통 정책이 달성할 수 있는 것은 아닙니다. 공개 정보로 가능한 값은 각각 3.6/4.2입니다. 내부 확인은 둘 다 3.0입니다.

무작위 정책의 적은 표본 평균은 우연히 기대값보다 낮아질 수 있습니다. 따라서 최적 비용과의 차이는 품질을 유지한 **결정적** 기준선을 대상으로 계산하고, 무작위 3seed 평균을 이론적 기대값과 혼동하지 않습니다.

## 검증과 재현

`protocol.json`에 비교 조건을 기록했습니다. 검사 중 기존 규칙의 동률 처리가 질문 ID 문자 정렬과 다르다는 것을 발견했습니다. 기존 검사를 바꾸지 않고, 공개 관찰로 원래 Context를 재구성해 **실제 제공 순서**를 재현하도록 고쳤습니다. 비용·분할·seed·보상은 바꾸지 않았습니다. 최종 결과는 `baselines-verified.json`이며 최초 구현 점검 실행과 구분합니다.

`cos-agent/`에서:

```powershell
uv run --locked --group rl-train python -m beauty_agent.afa.joint_baselines --report ../../../../outputs/afa-v2-baselines-v1/baselines-verified.json
uv run --locked --group rl-train pytest -q tests rl_tests ppo_tests
```

재실행 시 새 보고서 이름을 사용합니다. 결과·질문 추적·품질·비용·seed별 집계·복구 수·입력 및 코드 해시를 기록합니다. 정책/환경 오류는 비교를 중단하며 실패를 집계에서 숨기지 않습니다. 초안이 0건이면 조건부 초안 오류율은 null입니다.

## 다음 작업에 주는 결론

v2 PPO의 비교 기준은 단순 규칙이 아니라 **현재 가장 강한 계산 방식**입니다. v2 PPO 연결·학습으로 좋은 질문 순서를 재현하는지 확인할 수는 있지만, 이 고정 과제에서 질문 비용 우위를 입증할 목표로 진행해서는 안 됩니다.

실제 개선을 연구하려면 v67의 대화·후보·정정·제품 근거 등 더 넓은 문제를 어떤 상태·응답·비용 계약으로 연결할지 별도 검토해야 합니다. 기존 val/test나 비용을 PPO가 이기도록 다시 고르지 않습니다. 알려진 유한 문제에서 계산 방식으로 충분하다면 그 결과도 유지합니다.

`development_preview`, `production_enabled=false`, `human_review=unreviewed`, `approved_reference=false`를 유지합니다. 독립 제품/규칙 가족 평가나 사람 검토는 완료하지 않았습니다.

최종 비교 보고서는 루트 `outputs/afa-v2-baselines-v1/baselines-verified.json`입니다. 비용·품질·개선 여지·자료 구성과 코드/입력 해시를 별도 검증 기록에 남겼습니다. 기존 v1 모델·v2 응답 자료·실행 환경은 변경하지 않았고, 새 정책 학습이나 test 정책 점수 계산은 하지 않았습니다.
