# AFA Stage 3 — 전이·판정·비용·종료의 전수 검증

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

목적: **모델을 학습하기 전에 환경과 채점표의 빈틈을 찾는다.** Stage 2에서 API가 실행되는 것을 확인했고, 이번에는 모든 지원 경로가 명세대로 점수를 받고 종료하는지 검사한다. 아직 기준선 비교(Stage 4)나 RL 학습(Stage 5)을 실행한 것이 아니다.

## 무엇을 검사하는가?

`beauty_agent/afa/validation.py`는 10개 설계 세계를 모두 순회한다. 질문 순서를 하나 정해 실행하는 대신 다음을 검사한다.

- 모든 도달 가능한 질문 prefix에서 모든 enabled 질문·보류·초안 요청을 실행한다.
- 마스킹된 전역 사전의 행동도 각각 시도해 오류·상태 미변경을 확인한다.
- 초기화 시 숨은 행동 0회, 실행마다 dispatch 1회, 선택 답만 공개, 반환 공간·상태·마스크 일치를 확인한다.
- 종료 후 추가 step을 거부하고, 질문을 반복해 비용을 회피하거나 무한 진행할 수 없는지 확인한다.
- 같은 카드·공개 답·잔여 예산이 같으면 숨겨진 다른 답과 관계없이 관찰/마스크가 같은지 비교한다.

## 참조 계산은 환경과 어떻게 다른가?

환경의 `_encode`, `_mask`, reward/종료 함수를 정답으로 다시 호출하지 않는다. **RawReference**는 원본 PreviewEngine을 직접 호출하고, 정적 과제의 질문/행동 마스크·숫자 상태 offset·비용/종료를 별도로 계산한다. 그 결과와 실제 환경 transition을 대조한다.

공유하는 것은 기존 KB/규칙과 Stage 0 명세다. 따라서 이는 adapter·환경과 원본 규칙의 일치 검사이며 KB 자체의 도메인 타당성·임상 효과를 독립 검증한 것이 아니다. 소수의 의도적 reward/mask 오류를 넣었을 때 검사기가 실패하는지도 회귀 테스트한다.

Oracle은 현재 합성 세계의 참조다. reference/모든 답은 evaluator만 보며 정책 입력에는 넣지 않는다. branch ID·reason 문자열은 추적 정보로 남긴다. 동일 의미의 다른 분기는 허용하되 B-C02의 `inform_general_practice`와 `suggest_behavior_change` 차이를 임의로 동일 라벨로 바꾸지 않는다. 의미가 갈리는 9개 세계는 이전 단계의 제외 상태를 유지한다.

## 결과를 읽는 법

| 집계 | 의미 |
| --- | --- |
| 10 worlds | 이미 점검한 내부 설계 세계. 미열람 외부 평가가 아님 |
| 88 prefix states | 질문 순서별 도달 상태 수. 같은 공개 상태라도 순서가 다르면 중복될 수 있음 |
| 34 distinct public states | 카드·공개 값·잔여 예산이 같은 prefix를 합친 수 |
| 203 allowed transitions | 도달한 prefix에서 실행한 유효 행동 수. replay 내부 중복 실행 횟수는 제외 |
| 501 masked rejections | 도달한 prefix에서 거부해야 할 전역 사전 행동 검사 수 |
| 125 terminal paths | 중간 hold와 정상 완료를 포함한 전체 종료 경로 |

보고서는 각 세계의 정상/잘못된 종료 경로·return·분기 추적 차이를 보존한다. 가장 유리한 잘못된 종료도 가장 비용이 큰 유효 완료보다 낮은 return인지 확인한다. 현재 잘못된 종료 손실 5가 최대 질문 비용 4보다 크므로 최소 1단위의 차이가 있어야 한다.

**세계별 최선 경로는 hidden 답을 알고 전수 탐색한 hindsight 분석값**이다. 실제 정책이 선택 가능한 성능이나 학습 결과로 보고하지 않는다. 서로 구분되지 않는 공개 상태에서 세계마다 다른 질문을 고르는 최선 경로를 평균내어 정책 성능으로 쓰지 않는다.

## 정상 경로와 경계 검사를 구분한다

현재 known-answer 격자는 네 질문 이내에 지원 응답을 모두 얻는다. 정상 경로에서는 과제 예산 실패가 발생하지 않는다. 이를 검증했다고 과장하지 않고 별도 engineering probe로 다음을 확인한다.

| 경계 검사 | 확인할 사항 |
| --- | --- |
| 내부 잔여 질문 수를 1로 주입 | 부위 답 뒤 질문이 더 남으면 비용 1+예산 실패 손실 5, terminated=True |
| B-C01의 잔여 질문 수를 2로 주입 | 마지막 답을 얻은 뒤 예산 0이어도 무료 초안/정당한 보류를 선택할 수 있음 |
| 별도 B-B01 심한 통증 fixture | 원래 KB/Context의 필수 안전 보류만 enabled, 초안 제안 거부 |

이 주입은 테스트 작업 공간에만 적용한다. Stage 0 설정·Stage 1 분할·원본 KB·57개 감사를 수정하지 않으며 학습 사례로 내보내지 않는다. B-B01 검사는 안전 게이트 회귀이며 첫 과제의 카드 범위를 확대하거나 임상 안전을 입증한 것이 아니다.

외부 TimeLimit의 truncation/마지막 관찰은 Stage 2 검사에 포함돼 있다. 과제 예산 실패와 같은 것으로 처리하지 않는다. 현재 단계의 정적 known-answer 자료는 거절·정정·제품 조회 등 미래 확장의 모든 전이를 검증하지 않는다.

## 실행과 산출물

`cos-agent/`에서:

```powershell
uv run --group rl python -m beauty_agent.afa.validation --report ../../../../outputs/afa-stage3/exhaustive.json
uv run --group rl pytest -q tests rl_tests
```

검사기는 세계별 진행을 출력한다. 원본 KB 로드와 prefix replay를 반복하므로 일반 단위 검사보다 시간이 걸린다. 보고서의 숫자는 진단 coverage이며 정확도·학습 데이터 수·정책 성능이 아니다. 모든 내부 split을 API/채점 점검에 사용했음을 기록하며 이를 미노출 최종 평가라고 부르지 않는다.

보고서는 루트 `outputs/afa-stage3/`에만 쓴다. `exhaustive.json`에는 개별 유효 transition·종료 경로·분기 차이와 별도 경계 probe 결과를 담는다. JSON에 진단용 world fingerprint가 있어도 정책 관찰로 보내지 않는다.

## 다음 단계의 목적

**Stage 4는 검증된 환경에서 규칙·무작위·비용 기반 탐욕·BC 같은 기준선을 실제로 비교하는 단계**다. 이번 전수 검증은 그 비교를 위한 채점표 확인이며 기존 방식의 일반화 성능 측정이 아니다. 기준선도 숨겨진 개별 답을 미리 볼 수 없다.

`development_preview`, `production_enabled=false`를 유지한다. 관찰·설계값·기계적 참조·사람 판단을 구분하고, 제조사 선호를 reward/품질 점수로 사용하지 않는다.

## 실행 확인 — 2026-11-16
