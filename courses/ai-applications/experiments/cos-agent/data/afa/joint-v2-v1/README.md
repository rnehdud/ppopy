# v2 연습 환경 — 질문하고 답을 받는 프로그램

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

**48개 가상 상황을 실제로 실행할 수 있게 연결했습니다.** 아직 새 PPO 학습이나 기존 방식과의 성능 비교는 하지 않았습니다.

## 쉽게 보면 이렇게 작동합니다

1. 가상 상황 하나를 고릅니다. 전체 답은 프로그램 안에 숨깁니다.
2. 에이전트가 질문을 고릅니다. 처음에는 적용 부위부터 확인합니다.
3. 가상 사용자가 **그 질문의 답만** 돌려줍니다.
4. 프로그램이 답을 기록하고, 더 물을지·초안을 낼지·보류할지 다시 판단합니다.
5. 질문 부담과 종료 결과를 기록합니다.

예를 들어 아래 흐름을 실제 실행했습니다.

| 순서 | 에이전트 행동 | 프로그램이 확인한 것 |
| --- | --- | --- |
| 1 | 적용 부위 질문 | 그 답만 공개 |
| 2 | 물 온도 질문 | 그 답만 추가 공개 |
| 3 | 마찰 질문 | 도구에 따라 안내가 달라질 수 있어 아직 종료하지 않음 |
| 4 | 도구 질문 | 원래 엔진에서 사라졌던 질문을 v2 전용 처리로 확인 |
| 5 | 초안 요청 | 기존 실행 검사 통과 후 가상 제품의 표시 사용법 초안 생성 |

이 예시는 질문 연결을 확인하려고 의도적으로 고른 상황입니다. 학습한 정책의 성능 결과가 아닙니다. 초안은 기존 데모의 가상 제품 사용법이며 저장·승인·임상 검토된 개인화 안내가 아닙니다.

## 이번에 완성한 범위

| 구성 | 역할 |
| --- | --- |
| 응답 자료 48개 | 물 온도와 세안 방법을 함께 다루는 완결된 가상 답변표. 학습/내부 확인/내부 테스트 30/9/9 |
| v2 전용 실행 처리 | 필요한 도구 질문을 추가하고, 이전에 정한 의미 확정 기준을 초안 조건에 적용 |
| 연습 환경 | 질문 → 답 공개 → 기록 → 다음 행동 → 비용·종료까지 연결 |
| 검사 코드 | 같은 공개 답이면 같은 행동 조건인지, 답 누출·잘못된 행동·비용 계산 오류가 없는지 확인 |

기존 v1 환경·PPO 실행 코드·모델은 유지합니다. **기존 v67 데이터는 이번에도 학습 자료로 변환하지 않았습니다.** 이번 자료는 [앞서 정한 48개 설계](../scenario-plan-v2-v1/README.md)로부터 별도 생성했습니다.

## 질문을 추가하는 방식

`joint_runtime.py`는 기존 ActionContext의 복사본에만 v2 조건을 적용합니다. 원본 KB의 판정·문구·첫 분기 우선순위는 바꾸지 않습니다.

- 초안 허용은 **기존 초안 조건 AND v2 의미 확정 조건**입니다. 기존에 막힌 초안을 열어주지 않습니다.
- 필요한 도구 질문이 원본에서 닫혔다면, 해당 변수가 선택 카드에 속하고 `consumer_question_allowed=true`인지 확인합니다.
- 질문 문구는 기존 acquisition 항목의 `question_example`을 사용합니다. 제품 정보·미확인 후보를 사용자 질문으로 바꾸지 않습니다.
- 질문 확장이라는 개발용 근거를 Context에 명시합니다. 새 처리의 버전은 `afa-joint-runtime-0.1`입니다.
- 기존 `validate_action → decide_action → dispatch_action`을 그대로 통과합니다. 선택과 다른 fallback 행동이 실행되면 오류입니다.
- 모름·거절·충돌·명시적 정정의 공개 예시 9개도 이 실행 처리에서 실제 질문/보류/초안으로 연결해 검사합니다. 이 예시들은 학습·정책 점수 계산 대상이 아닙니다.

기존 KB/Context가 원래 tools 질문을 내지 않는 상태도 보존 검사합니다. 전체 안전 카드·제품 조회·실사용을 새로 지원했다고 표현하지 않습니다.

## 답변 기록과 오류 처리

관찰 준비와 행동 실행을 분리합니다. 새 답은 다음 판단을 위해 준비하고, 행동을 실제 실행할 때 상태에 반영합니다. 질문 요청 자체가 답변을 확인한 것이 되지는 않습니다.

초기화에서는 행동을 실행하지 않고, 정상 step마다 dispatcher를 한 번만 호출합니다. 실행 중에는 준비 상태를 바꾸거나 같은 행동을 중복 실행할 수 없습니다. 정정은 과거 이벤트를 남긴 채 새 이벤트로 처리하고, 이전 판단 토큰을 무효화합니다.

환경은 임시 메모리 복사본에서 행동·답 반영·비용·출력 생성을 끝낸 다음 결과를 반영합니다. 답이 없거나 출력 생성이 실패하면 원래 상태·행동 수·예산을 유지합니다. 이는 외부 부작용이 없는 합성 데모의 메모리 보호이며 DB나 실제 외부 작업을 되돌리는 기능은 아닙니다.

## 입력·행동·비용의 기술 규격

새 환경은 `JointAFAEnv`입니다. [Gymnasium Env API](https://gymnasium.farama.org/api/env/)에 따라 reset은 관찰/info, step은 관찰/reward/terminated/truncated/info를 반환합니다. `action_masks()`는 현재 가능한 고정 행동을 나타냅니다. 마스크를 무시한 행동은 상태를 바꾸지 않고 오류로 처리합니다.

| 공개 관찰 항목 | 차원 |
| --- | ---: |
| 질문 슬롯 5개의 상태 | 30 |
| 확인된 값 또는 null | 17 |
| 두 카드가 모두 선택된 과제 표시 | 2 |
| 행동 마스크 | 8 |
| 남은 질문 수 | 1 |
| 슬롯별 질문 비용 | 5 |
| 남은 질문 비용 예산 | 1 |
| 합계 | **64** |

행동 인덱스 8개는 기존의 질문 5개·보류 2개·초안 1개를 유지합니다. 실제 세계 ID·전체 답·참조·가족 ID는 정책 관찰이나 info에 넣지 않습니다. 비용 조건은 공개하므로 같은 상황에서도 비용이 다른 경우를 구분할 수 있습니다. **기존 v1 모델 입력은 58차원이므로 그대로 연결하지 않습니다.**

기본 질문 비용은 모두 1, 최대 5회, 잘못된 종료 손실 6입니다. 별도 비용 조건은 마찰·건조 2, 나머지 1, 최대 총비용 7, 잘못된 종료 손실 8입니다. 실제 피로·시간 측정값은 아닙니다. 마지막 답을 받은 뒤 올바른 무료 종료를 허용하고, 과제 예산 소진과 외부 TimeLimit truncation을 구분합니다. 보류만 빨리 골라 비용을 줄이는 것은 정상 완료보다 유리하게 채점하지 않습니다.

## 실행용 자료와 재현

이 폴더의 train/val_internal/test_internal JSONL은 생성 코드로 재현됩니다. 각 행은 초기 공개 관찰을 비워두고, `environment_only`에 5개 슬롯의 응답표·기계적 참조·기대 종료 종류를 둡니다. 모델에 그 객체를 전달하지 않습니다.

`manifest.json`은 계획·의미 계약·생성 코드·원본 source 해시, 파일 해시, 가족 배정과 개수를 기록합니다. 초기 설계의 가족 배정 16개와 30/9/9를 유지합니다. 현재 자료는 이미 점검한 합성 domain이며 독립 최종 평가셋이 아닙니다. 사람 검토 상태도 계속 unreviewed/approved_reference=false입니다.

`cos-agent/`에서:

```powershell
# 기존 bundle을 다시 생성해 바이트 단위로 대조. 덮어쓰지 않음.
uv run --locked --group rl-train python -m beauty_agent.afa.joint_data verify

# 모든 core 상황과 비용 조건의 동작 검사. 보고서 재실행에는 새 이름 사용.
uv run --locked --group rl-train python -m beauty_agent.afa.joint_validation --report ../../../../outputs/afa-v2-joint-v1/exhaustive-verified.json

uv run --locked --group rl-train pytest -q tests rl_tests ppo_tests
```

처음 자료를 만드는 경우만 `joint_data build`를 사용합니다. 이미 있는 bundle은 덮어쓰지 않습니다. 생성 파일은 명시적인 합성 입력이며 실제 사용자나 v67 기록을 복사하지 않았습니다.

## 검사 범위와 다음 단계

전체 검사는 학습·내부 확인·내부 테스트의 48개 상황을 두 비용 조건에서 점검합니다. 모든 도달 가능한 공개 상태에서 유효 행동과 금지 행동을 확인합니다. 같은 공개 상태로 합쳐지는 질문 순서는 묶어 계산하므로 수치를 데이터 크기나 정책 정확도로 해석하지 않습니다. 의미 판정은 앞 단계의 같은 계약을 사용하며, 독립적인 도메인 정답 검증은 아닙니다.

별도 검사는 답 공개 제한, 원본 Context 보존, 실제 dispatch, 중복 실행·오래된 판단·실패 복구, 9개 까다로운 답변 예시, 비용 차이, 마지막 무료 종료, 예산 소진, 외부 시간 제한을 다룹니다.

**다음은 이 환경에서 기존 질문 방식들을 실행해 비교 기준을 측정하는 것**입니다. 새 학습 전에 어느 방식이 얼마나 묻는지, 같은 안내 수준에서 줄일 여지가 있는지 먼저 확인합니다. 이 작업이 끝나야 v2 학습 계획을 고정하고 PPO를 연결합니다. `development_preview`, `production_enabled=false`를 유지합니다.
