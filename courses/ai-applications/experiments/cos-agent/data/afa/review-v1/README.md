# AFA Stage 0~4 개선 검토 — 학습 연결과 성능 검증 분리

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

목적: **현재 환경으로 확인할 수 있는 것과, 과제를 확장해야 확인할 수 있는 것을 구분한다.** PPO-23의 Stage 0~4를 대체하거나 v1 데이터/보상/분할을 다시 선정하지 않는다. 이 문서는 Stage 4 이후의 보완 작업이며 Stage 5 학습 완료 기록이 아니다.

## 전체 진행과 현재 위치

범위·성공 기준 → 응답 세계 → 환경 → 전이·보상 검증 → 기준선 비교 → **현재: 학습 전 보완** → Stage 5 연결 점검 → 성능 평가 → 에이전트 연결·확장.

| 구분 | 지금 할 일 | 완료 근거 | 남은 일 |
| --- | --- | --- | --- |
| v1 보존 | 기존 결과·분할·보상·KB를 유지 | Stage 0~4 자료와 기존 보고서를 덮어쓰지 않음 | 버전별 비교 기록 유지 |
| 개선 여지 | 실제 공개 정보로 선택 가능한 최적 비용 계산 | `readiness.py`의 posterior 기반 전수 계획 | v2의 더 넓은 분포에서도 계산 |
| 의미 충돌 | 제외 세계마다 full 결과와 질문 순서별 결과를 나란히 보존 | 보고서 `semantic_review_queue` 9개 | 의미 계약·독립 검토; 해결 전 학습에 포함 금지 |
| 실행 비용 | KB 재로드와 격리 메모리 복사의 비용 측정 | `runtime_profile`, 20회/방식 | 실제 rollout 단계별 프로파일 |
| 재현성 | 명시한 세계로 reset할 때 난수열 소비 방지 | 환경 회귀 검사 | PPO collector·evaluation mask 연결 검사 |
| 성능 평가 | 작은 내부 자료와 독립 평가 구분 | v1 효율 주장 불가·독립 평가 미준비 상태 명시 | 별도 가족 분할과 검토된 참조 |

## 1. 숨겨진 세계별 하한과 실제 선택 가능한 정책을 구분

기존 Stage 4의 hindsight 하한은 세계별 전체 답을 보고 최선 질문 순서를 고른다. 이번 진단은 **현재 공개 답과 일치하는 세계들의 posterior를 유지하고, 같은 공개 상태에서는 하나의 행동만 선택**한다. 질문 답으로 posterior가 갈라진 이후에만 다른 행동을 고를 수 있다. 모든 지원 세계에서 올바르게 종료한다는 제약 아래 기대 질문 비용을 동적 계획법으로 최소화한다.

| 자료 | 세계별 hindsight | 공개 정보 기반 최적 비용 | 기존 규칙 | train 기반 탐욕 |
| --- | ---: | ---: | ---: | ---: |
| train 6개 | 2.333 | **2.500** | 3.333 | **2.500** |
| val 2개 | 2.000 | **2.000** | **2.000** | 2.500 |

train의 2.333은 실제 공통 정책으로 달성할 수 없다. 현재 탐욕 기준선은 train에서 이미 공개 정보 기준 최적이다. val에서는 기존 규칙이 최적이다. 따라서 **현재 v1의 가장 강한 품질 유지 기준선보다 질문 수를 줄이는 성능 주장은 불가**하다. 종료 품질을 낮춰 질문만 줄이는 방법은 개선으로 인정하지 않는다.

이 최적 계획은 진단 대상 split의 전체 응답 분포를 알고 계산한다. 실제 세계 ID를 행동 선택에 쓰지는 않지만 **평가 분포를 아는 evaluator-only 분석**이다. train-only로 학습한 정책·독립 성능·배포 기준선으로 사용하지 않는다. test_internal은 점수 계산 대상에 넣지 않는다. 모든 v1 세계는 이전 기계 검증에서 점검했으므로 미노출 평가 자료로 부르지 않는다.

## 2. 분기 의미는 자동 통합하지 않는다

B-C02의 혼합 세계에서는 `inform_general_practice`와 `suggest_behavior_change`가 질문 순서에 따라 달라진다. 보고서는 전체 답의 참조와 각 종료 경로의 의미·branch ID를 보존한다. branch ID 차이 자체를 오답으로 삼지는 않지만, action 의미 차이를 무시하지도 않는다.

**확장 전 필요한 결정:** 첫 분기만 결과로 내는 정책을 유지할지, 서로 양립 가능한 여러 권고를 합칠지, 추가 질문을 요구할지 정한다. 이 선택은 KB 의미 변경이므로 별도 버전·검토·기존 회귀 결과와의 차이 기록이 필요하다. 현재 원본 엔진을 고치거나 9개 세계를 정답으로 승인하지 않았다.

## 3. 성능 개선은 측정한 뒤 적용

현재 fork는 새 KB adapter를 생성한다. 로컬 20회 측정에서 재로드 fork 중앙값은 약 13.5ms, 전체 격리 메모리 복사는 약 23.2ms였다. 전체 복사는 오히려 느려 **채택하지 않았다**. 숫자는 해당 로컬 실행의 fork 비용이며 rollout 전체·PPO 학습 속도가 아니다.

다음 학습 연결 단계에서 reset/KB 평가/상태 직렬화/dispatch/정책 추론을 구분해 측정한다. KB 캐시를 도입한다면 데이터 불변성·세션 간 격리·실패 롤백을 함께 검증한다. 검증을 생략하거나 수정 가능한 KB를 여러 환경이 공유하는 방식으로 최적화하지 않는다.

## 4. 다음 두 작업의 요구사항

### Stage 5A — v1 Maskable PPO 연결 점검

목적은 학습 API와 마스크·종료 연결 확인이다. 질문 효율 우위 실험으로 발표하지 않는다.

- Torch/SB3/sb3-contrib는 별도 선택 의존성 그룹으로 격리하고 공식 지원 Python/Gym 조합을 확인한다. 현재 설치·학습하지 않았다.
- train만 rollout/학습에 사용하고 seed·버전·총 step·gamma=1·shaping=0을 기록한다. test 평가와 val 기반 탐색을 하지 않는다.
- 수집 시 모든 선택이 해당 상태의 마스크를 따르는지, 평가에도 mask-aware 함수를 쓰는지 확인한다. invalid action의 hard error는 유지한다.
- reset 숨은 행동 0회, 정상 step당 dispatch 1회, terminal/truncation·bootstrap 계약을 유지한다. 일반 무작위 action checker로 마스크를 무시한 오류를 정상 동작으로 바꾸지 않는다.
- 가중치·실행 로그는 outputs에 저장한다. 통과 기준은 학습 완료·유한 수치·금지 행동 0·관찰 누출 0·재로드 후 mask-aware 실행 성공이다. 보상 상승만을 통과 기준으로 쓰지 않는다.

### Stage 4B — v2 성능 검증 과제 설계

목적은 질문 순서 및 정보 획득 가치의 개선을 평가할 조건 확보다. 아래 [v2 설계 요구사항](../benchmark-v2-design/README.md)을 확정한 후 별도 데이터를 생성한다. 기존 v1 val/test를 점수가 좋아지도록 재선정하지 않는다.

## 재현

`cos-agent/`에서:

```powershell
uv run --group rl python -m beauty_agent.afa.readiness --report ../../../../outputs/afa-review-v1/readiness.json
uv run --group rl pytest -q tests rl_tests
```

성능 비교 착수 전 자동 검사에는 같은 명령에 `--require-efficiency-headroom`을 추가한다. 현재 v1에서는 보고서를 저장한 후 종료 코드 **1**을 반환한다. 개선 여지가 없다는 예상 결과이며 테스트 실패를 숨기거나 학습 연결 점검까지 금지하는 기능은 아니다. 종료 코드 0도 독립 평가·도메인 승인을 대신하지 않는다.

보고서는 raw semantic witness를 포함한 합성 진단 자료이며 정책에 넘기지 않는다. 코드/계약 해시를 함께 기록한다. 기존 Stage 4 보고서·검증 인덱스는 당시 실행 기록으로 보존하며, 변경 후 검증은 별도 디렉터리에 남긴다. `development_preview`, `production_enabled=false`, `human_review=unreviewed` 경계를 유지한다.

## 실행 확인 — 2026-11-16

실험·RL 검사 356개 통과(신규 5개), 기존 Starlette/httpx 경고 1건. 현재 명세 검사 371개, source manifest 27/27, KB 구조 95/95 통과. 전수 환경 진단은 기존과 같은 10세계·203개 유효 전이·501개 거부·125개 종료 경로이며, 5개 기준선의 120개 episode도 기존 결과를 재현했다. test_internal은 기존과 같이 환경 기계 검증에만 사용하고 정책 성능을 측정하지 않았다.

엄격 원본 검사는 62 통과/기존 5 실패, 감사는 52/57 및 종료 코드 1을 유지했다. coverage 60카드/213분기/180경계, 합성 CLI production_enabled=false 확인. 새 보고서와 코드 해시는 루트 `outputs/afa-review-v1/`에 보존한다. v2 구현·전문가 검토·PPO 학습·앱 연결은 수행하지 않았다.
