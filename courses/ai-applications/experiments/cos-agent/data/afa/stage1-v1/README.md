# AFA Stage 1 v1 — 응답 완결성과 내부 분할

해당 버전의 실험 기록이다. 현재 에이전트에서 AFA가 맡는 역할은 [목표 구조](../../../docs/agent-runtime-target.md)를 참고한다.

목적: **정책이 질문 순서를 바꾸어도 정의된 합성 답을 받고, 같은 세계의 변형이 분할을 넘지 않게 한다.** [Stage 0](../stage0-v1/README.md)의 비용·의미 계약은 변경하지 않는다. 아직 Gym 환경·학습 정책은 없다.

## 이번 산출물

| 자료 | 의미 |
| --- | --- |
| `train.jsonl` | 환경 개발용 합성 세계 6개 |
| `val_internal.jsonl` | 내부 검증용 세계 2개 |
| `test_internal.jsonl` | 설정 고정 후 내부 점검용 세계 2개 |
| `manifest.json` | 생성 규칙·입력/출력 해시·분할·제외 통계·한계 |
| 루트 `outputs/afa-stage1/v67-support.json` | v67 1,025개 시나리오의 실제 분할·계보·그대로 재사용할 수 없는 이유 |

이 10개는 **Stage 0의 별도 설계 격자에서 나온 자료**다. v67의 기록이나 제품을 바꾼 파생본이 아니다. `parent_world_id`는 Stage 0 세계를 가리키고 `v67_parent=null`이다. 모든 자료는 synthetic, `human_review=unreviewed`, `approved_reference=false`, `training_ready=false`다. 실행용 응답표가 있다는 것과 독립 정답/학습 품질 승인은 다르다.

## v67 감사 결과를 어떻게 읽어야 하는가?

v67 무결성 검사를 먼저 통과한 뒤 SFT의 실제 시나리오 소속으로 train/val/test를 찾는다. canonical의 원래 `split=train`은 생성 풀 표시로만 남긴다. 기존 858/76/91개 시나리오의 소속과 부모 계보는 감사 보고서에 보존한다.

**엄격한 Stage 0 입력 계약에 수정 없이 맞는 원본 시나리오는 0개**다. 이는 v67 전체가 쓸모없거나 모든 답이 누락됐다는 뜻이 아니다. 첫 실험은 `demo-cleanser/fixture-v1`과 확인된 고정 프로필, 단일 정적 카드/응답으로 제한했다. 원본의 다른 제품·프로필·정정/후보 과제를 이 형식으로 바꾸지 않았다.

| 제외 이유 | 관찰 수 |
| --- | --- |
| B-C01/B-C02 단일 카드 범위 밖 | 423 |
| 선택 카드지만 초기 프로필/제품이 Stage 0 fixture와 다름 | 602 |
| 여러 턴이라 이벤트 모델이 필요 | 576 |
| 단일 턴 응답표에 필수 슬롯 누락 | 8 |
| 단일 턴 응답의 상태/값/시각 계약이 첫 범위 밖 | 14 |

이유는 중복 집계다. 범위 밖 카드는 조기 제외하고, 여러 턴은 정정 가능성을 보존하기 위해 **값을 합쳐 정적 세계로 만들지 않으며** 이후 단일 턴 응답 완결성 수치에 포함하지 않는다. 따라서 8/14를 v67 전체의 결측률로 해석하면 안 된다. 원본 제품을 demo 제품으로 바꾸거나 마지막 답을 첫 턴에 주입하지 않는다.

지원하지 않는 자료는 감사 대상으로 남기고 실행 번들에 섞지 않는다. 향후 v67 파생 fixture가 필요하면 별도 버전에서 원본 scenario_id·그룹/가족·분할과 새 합성 값의 출처를 연결한다. 이번 번들은 그런 변환을 수행하지 않았다.

## 실행 번들의 응답·공개 경계

각 세계는 Stage 0에서 모든 지원 질문 순서의 의미 서명을 검사한 10개 중 하나다. B-C01 3개/B-C02 7개를 사용하며 action 의미가 갈리는 나머지 9개는 제외 상태를 유지한다.

- `initial_visible_observations={}`: 처음에는 답이 공개되지 않는다.
- `environment_only.response_table`: 카드가 물을 수 있는 각 슬롯의 정형 합성 답변. 부위 face도 질문 후에만 공개한다.
- `environment_only.reference` / `reference_terminal`: 고정 엔진에서 계산한 기계적 참조다. 환경/평가 전용이다.
- ID·parent·split·provenance·전체 응답표·참조를 정책 입력으로 전달하지 않는다. 정책 입력 인코더는 Stage 2에서 구현한다.
- 답변 요청 자체로 모든 값을 확인 완료하지 않는다. 환경은 선택한 질문의 슬롯만 정형 관찰로 반영해야 한다.

단순 슬롯 수가 아니라 기존 Stage 0 검사기가 **도달 가능한 모든 지원 질문 순서**에서 응답 존재·재질문 부재·게이트·참조 일치를 확인한다. 비정적 사건/거절/충돌/제품 조회는 이 known-answer 격자의 지원 범위가 아니다.

## 분할 규칙과 한계

각 카드 안에서 `(card, 정렬된 답변 객체)`의 SHA-256으로 정렬한 뒤 첫 세계는 val_internal, 두 번째는 test_internal, 나머지는 train이다. 분할 규칙은 결과 점수·행동 라벨·v67 test 소속을 사용하지 않는다. 각 분할에 두 카드가 포함된다.

분할 단위는 **턴이나 질문 순서가 아닌 세계 전체**다. 같은 세계의 모든 질문 순서·반복 seed·향후 변형은 부모 분할을 상속해야 한다. 검증기는 동일 응답 세계와 동일 부모가 여러 레코드/분할에 나타나면 거부한다. 생성 파일도 바이트/해시로 재현 검사한다.

그러나 이 자료는 이미 점검한 10개 설계 세계이며 같은 규칙·제품·템플릿 풀이다. 의미 가족·제품 가족이 독립 분리된 외부 holdout이 아니다. 6/2/2라는 작은 내부 분할에서 모델 일반화·사용자 효용을 주장하지 않는다. 환경 인터페이스와 재현 절차를 개발하기 위한 분할이다. 독립 평가 준비는 이후 Stage 9다.

v67 전체 무결성 감사에는 기존 test 구조와 계약 검사도 포함된다. test를 전혀 열람하지 않은 상태라고 표현하지 않는다. 원본 output 라벨을 새 정책 보상/참조/분할 선택에 복사하지 않았다.

## 재현 명령

`cos-agent/`에서 기존 파일을 확인한다:

```powershell
uv run python -m beauty_agent.afa.stage1 verify --report ../../../../outputs/afa-stage1/v67-support.json
uv run pytest -q tests/test_afa_stage0.py tests/test_afa_stage1.py
```

새 출력 위치로 재생성할 때만 build를 사용한다. 기존 번들은 덮어쓰지 않는다.

```powershell
uv run python -m beauty_agent.afa.stage1 build --bundle ../../../../outputs/afa-stage1/rebuild --report ../../../../outputs/afa-stage1/rebuild-support.json
```

두 번째 build의 동일 경로 재사용은 오류다. 입력/생성기/Stage 0 검사기 변경 시 manifest 재현이 실패하므로 원인을 검토하고 새 버전으로 갱신한다. 기존 KB 원본 manifest나 v67 해시를 고쳐 실패를 숨기지 않는다.

## 다음 작업의 목적

**Stage 2는 이 응답표로 실제 환경 한 턴을 만드는 단계**다. 현재 상태 준비와 선택 행동 실행을 분리하고, 질문한 답만 공개하며 다음 관찰·마스크를 계산한다. Stage 1까지의 자료 준비를 Gym 환경·학습·모델 평가 완료로 해석하지 않는다. 항상 `development_preview`, `production_enabled=false`를 유지한다.
