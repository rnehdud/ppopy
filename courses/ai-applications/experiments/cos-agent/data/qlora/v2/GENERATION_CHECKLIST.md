# 500턴 Critic 피드백을 반영한 신규 생성·수정 기준

## 900턴 통합 Critic에서 추가 확인한 경계

- `9eb1d30`의 실제 통합 검수는 883 PASS / 17 FAIL이에요. 최종 17건은 입력을 그대로 두고 답변만 수정하며 별도 재검수를 받아요.
- 제품 ID에 들어 있는 `thin` 같은 식별 문자열은 성상 관찰이 아니에요. 미제공 묽어짐·거품·시트·통·상자·뚜껑을 제품이나 사건의 사실로 바꾸지 않아요.
- 일반 문헌의 사례·제거 범위를 특정 제품에서 확인한 표시로 옮기지 않아요.
- 부정문에도 사실 전제가 있어요. “다른 제품을 쓴 친구”, “눌릴 때뿐 아니라”처럼 미확인 제품 사용·접촉 사건을 전제하지 않아요.
- 가벼운 접촉, 고개를 숙임, 짧은 물 접촉 같은 강도·자세·시간은 실제 슬롯에 있을 때만 서술해요.
- 17건을 수정했다고 외부 PASS로 바꾸지 않아요. `stage1_critic.jsonl` 원본은 외부 재검수 결과를 받기 전까지 보존해요.

`8ad8ecd`의 `reviews/stage2_500_critic.jsonl`은 실제 외부 검수 기록이에요. 486 PASS / 14 FAIL이며 14건의 지적은 모두 `fact_distortion`이에요. 새 400턴 생성 담당에게 아래 기준을 전달했고 동일 기준으로 작성 중 자체 점검해요. 자체 점검은 외부 교차 검수가 아니에요.

## 생성 프롬프트에 추가한 조건

> 답변에서 사용자 사실로 쓰는 시간·기간·횟수·장소·제품 유형·색상·냄새·용기·증상 양상은 반드시 실제 SLMRequest의 confirmed_observations 또는 product_evidence에서 확인되어야 해요. 원래 합성 발화가 보조 기록에만 있고 정형 입력에 빠졌다면 모델은 그 사실을 모르는 것으로 취급해요. 문장을 자연스럽게 만들기 위해 세부사항을 추가하지 않아요. 빈 product_evidence만으로 제품의 제형이나 종류를 추정하지 않아요. 관찰에도 유형이 없으면 제품/내용물 등 중립어를 사용해요. 다른 관찰의 시점을 증상 시점으로 옮겨 붙이지 않아요. 문헌에서 제시한 일반 원리·조건은 사용자나 해당 제품에서 실제 관찰된 결과와 구분해요.

## 작성 순서

1. 합성 사용자 발화와 별도 확인을 먼저 설계하고 입력의 정형 슬롯·제품 근거로 옮겨 고정해요.
2. 답변을 개별 작성하면서 사용자 사실은 해당 슬롯/제품 근거, 일반 설명은 허용 문헌 구절에 연결해요.
3. 다음 항목을 실제 입력과 다시 대조하고, 근거가 없는 수식은 삭제해요. 이미 작성한 답변을 정당화하려고 입력에 사실을 만들어 넣지 않아요.
4. 수정 전후 원문과 해시를 보존하고 외부 재검수 요청을 만들어요. 사람 확인 전 `human_review=unreviewed`를 유지해요.

| 점검 대상 | 잘못된 보완 예 | 적용 원칙 |
|---|---|---|
| 시간·기간·횟수 | 오늘, 아침에 두 번, 남은 근무 주간, 저녁까지 | 서로 다른 사건의 시점을 합치거나 미제공 횟수를 추가하지 않아요. |
| 제품·제형·색·냄새 | 보습 크림, 연보라, 페인트 냄새 | 관찰/제품 근거에 명시된 수준까지만 표현해요. |
| 위치·용기·수량 | 병 입구, 욕실장, 가운데, 두 통/두 층 | 추론으로 구체화하지 않고 제공된 공간·대상·수량만 유지해요. |
| 증상 양상 | 식사할 때 더 심함, 밤에 깬 뒤 | 특정 활동 전후라는 사실과 악화·각성 사건을 구분해요. |
| 부정·미상 | 증상 없음, 서로 다른 제품 | 미상을 없음으로, 동일성 미상을 별개 제품으로 바꾸지 않아요. |
| 보류 안내 | 미제공 품목을 전제로 한 보류·다음 단계 | 보류 이유도 입력 사실에 한정하고 제품/루틴/세안·도포 지시를 추가하지 않아요. |
| 문헌·방해 청크 | 적용하지 않겠다는 방해 주제 언급 | 허용 근거의 범위를 지키고 방해 청크의 주제 자체를 답변에서 사용하지 않아요. |

## 검수 이력과 최종 파일의 관계

- `qlora_solution_hold_v2_checkpoint_500.jsonl`과 `reviews/stage2_500_critic.jsonl`은 **수정 전 감사용 동결본**이에요. FAIL 14건을 포함하므로 그대로 최종 학습에 쓰지 않아요.
- 수정된 14건은 신규 400건과 함께 `qlora_solution_hold_v2.jsonl`에 반영해요. 기존 입력은 수정하지 않아요.
- `reviews/stage2_14_corrections.jsonl`에 기존 Critic 원문, 수정 전후 답변, 실제 입력, 이전·현재 content SHA-256을 기록해요.
- `reviews/stage2_414_critic_requests.jsonl`은 수정 14건 + 신규 400건의 **검수 요청**이에요. 14개 배치(29~30행)로 나누고 결과/PASS를 대신 만들지 않아요.
- 기존 PASS 486건은 최종 파일과 content SHA-256을 대조해 내용이 그대로인 경우에만 기존 검수의 적용 범위로 인정해요.
- `reviews/stage1_critic.jsonl` 최종 통합 결과는 실제 재검수 결과를 받은 뒤에만 만들어요. 현재 미실시 검수를 PASS로 적거나 사람 승인을 대신 기록하지 않아요.
