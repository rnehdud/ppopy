# v67 공유 전 최종 검토

검토자: Codex(AI). 대상: 사용자가 3분할을 완료한 `v67-sft-export-1.2`와 연결된 canonical 스냅샷. 사용자가 요청한 개발 자료 공유 검토이며 사람·도메인 승인 기록은 아니다.

## 검토 결과

- 1,025개 합성 시나리오, 2,453턴. train 1,980 / val_internal 221 / test_internal 252턴.
- 분할 전후 ID와 `split` 이외의 필드가 모두 동일함을 확인했다. 라벨·관찰·발화를 이번 공유 작업에서 다시 작성하지 않았다.
- 원본·3개 SFT 파일의 SHA-256을 manifest와 대조한다. 전체 턴과 시나리오 포함 여부, ID 중복, 액션 분포를 검사한다.
- 실제 3분할 기준 group_id / scenario_family_id / product_family_id / 정규화 발화 / 기록된 derived_from 계보의 교차 중복을 검사한다. 모두 0건이다.
- 2,453턴 전체의 ActionContext·ActionProposal 스키마, 활성 액션/대상, 허용 근거 참조를 실행 계약으로 검사했다. 자유 질문 문구의 런타임 대체는 0건이다.
- 필수 보류 누락, 제품 사실을 사용자에게 질문, 확인된 known/unknown/declined/not_applicable 재질문, 충돌 관찰에 대한 일반 질문, 초안 선행조건 우회에 대한 명시적 정책 점검을 수행한다.
- 합성 입력과 `development_preview`, `production_enabled=false` 경계를 유지한다.

정량 검사 결과는 함께 제공한 `share-verification.json`에서 확인할 수 있다. 검사 도구의 오류 탐지·변환 회귀 테스트는 `test_dataset_cli.py`로 재현한다.

## 공유를 위해 정리한 사항

1. 원본 canonical의 모든 `split=train`은 생성 풀 표기다. 이 값만 사용하면 3분할을 잃는다. AFA 내보내기 도구는 실제 SFT의 시나리오 소속으로 분할하고 `source_pool_split`을 보존한다.
2. 기존 manifest의 경계 설명은 val_internal만 언급한다. test_internal도 같은 생성·제품 풀의 내부 분할이다. 별도 제품·출처로 구성한 독립 평가셋은 아직 아니다.
3. 기존 export의 `approved_reference=true`는 에이전트 정책 감사 기반 합성 SFT 사용 표시다. canonical의 사람 미검토 상태와 구분하며 사람이 독립적으로 검토한 정답이라고 기술하지 않는다.
4. AFA용으로는 기록된 경로와 이벤트만 제공한다. 임의 질문 순서의 반사실적 응답, 정적인 완전 프로필, 보상, RL 환경 구현까지 있다고 해석하지 않는다.
5. 문자 길이를 토큰 길이로 사용하지 않는다. 전체 학습 전에 모델별 토큰 길이와 assistant-only loss mask를 확인한다.

## 검토의 한계와 사용 규칙

모든 자유 문구의 의미적 정확성·최적 질문 선택을 독립적으로 판정한 결과가 아니다. 구조·계약 통과율을 모델 정확도나 임상적 효과로 보고하지 않는다. 각 상태에 타당한 다른 다음 액션이 존재할 수 있다. 작성 제안과 기준선 라벨이 섞인 점도 평가에 명시한다.

train은 가중치 학습, validation은 설정 선택, test는 고정된 설정의 내부 최종 비교에 사용한다. test 결과를 보고 수정하면 이후 결과는 같은 고정 test의 독립 성능이 아니다. 기존에 개발에 노출된 생성 풀을 재분할한 점을 보고서에 남긴다.

기존 원본 57시나리오 감사의 5개 불일치는 유지한다. 이 자료를 이용한 성공 결과가 원본 수용 기준의 충족이나 운영 활성화를 뜻하지 않는다.
