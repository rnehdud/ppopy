# 평가 계획

현재 pytest는 합성 계약에 대한 개발 회귀 검사입니다. 사람 평가, 실제 SLM 성능, 기존 엔진 대비 개선이나 실제 제품 효능 평가가 아닙니다. 모델 네트워크 경로는 모의 응답으로만 검증합니다.

필수 개발 검사: 정상 초안·반복 hash, iOS/미러/웹 계약 일치, 미확인 프로필/제품·버전 불일치 보류, 제외 제품 제거·모두 제외 보류, 중복/추가 필드/실사용 컨텍스트 거부, 오류 입력 비반향, 사용자 지시문의 확인 우회 차단, 모델의 정상/잘못된 ID/깨진 JSON/타임아웃 처리, 합성 근거 ID 존재.

다음 평가셋은 ERI-11에 맞춰 30개 이상의 시나리오와 기대 행동을 미리 고정합니다. 개발용과 최종 확인용을 분리하고, 같은 제품·프로필·규칙·초기 상태에서 기준선과 모델 경로를 비교합니다. 작업 성공률, 질문 적절성, 근거 내용의 충실도, p50/p95 지연, 모델 호출 수와 실패율을 보고합니다. 보류가 기대 행동인 사례와 정상 추천 성공을 구분합니다.

승인/저장 구현 시 다른 사용자 접근·무승인·만료/취소/수정 후 승인·중복 요청·동시 수정·Tool 장애 사례를 추가합니다. 권한 위반/무승인 쓰기 0건은 고정 시험 범위의 통과 기준이지 일반 안전성 보증이 아닙니다.

SLM 학습은 제품/실질 처방/주장 변형을 같은 그룹에 묶어 train/validation/test로 분리하고, 사람 미확정 라벨은 정답 평가에서 제외합니다. 형식 준수와 사실/판정 정확도를 따로 측정합니다. 고정 근거 ID 존재만으로 설명이 정확하다고 보지 않습니다.

## 액션 중심 오프라인 평가 준비 — 2026-11-10

현재 작업은 사용자와 합의한 액션 중심 평가 준비에 근거합니다. 위 ERI-11 언급은 기존 문서의 이력이며 현재 요구사항으로 재확인한 것은 아닙니다.

[액션 판정 기준](action-evaluation-rubric.md)과 [합성 사례·CLI 안내](../evaluation/action_policy/README.md)에 6개 액션의 실행/확인 경계, 미검토 개발 20개·holdout 후보 10개, 분할 검사와 재생 명령을 정리했습니다. 모델을 실행하지 않고 기존 규칙 기준선을 고정 상태에서 비교할 수 있습니다. 작성된 허용 집합에 없는 실행 가능 대안은 명시적 금지와 구분합니다.

사람 검토 전의 기계적 일치 수는 품질 정확도가 아닙니다. reviewed/approved_reference 판정이 없는 현재 자료에서는 정답 분모가 0이며 정확도는 null입니다. 제안·검증·문구 대체·fallback·실제 적용 결과와 전체 표시 질문을 분리하고, 사용자 분기가 없는 재생을 대화 완료로 집계하지 않습니다.

다음 사람 검토에서는 액션/대상·이유·필수 확인·상태 보존·허용 대안을 확인하고 실제 검토자/일자만 기록합니다. 이견은 disputed로 유지하고, 원형·제품군·유사성 검토와 버전/해시 고정 후 정답 사용 여부를 명시합니다. 에이전트 상호 리뷰는 이 사람 판정을 대체하지 않습니다. 실제 Qwen 추론·독립 최종 시험·SFT와 도메인 승인은 아직 완료되지 않았습니다.
