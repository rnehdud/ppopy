## 1. 개요 (Summary)

사용자가 스마트미러나 앱에 자연어(음성/텍스트)로 말하는 한 문장에는 여러 제품의 사용 사실, 사용 계획, 부정, 증상, 시간 등이 복합적으로 섞여 있습니다.
기존 PoC에서는 이를 **문장부호(쉼표, 마침표)와 띄어쓰기(어절)**에 의존해 자르다 보니, 실제 구어체나 문장부호가 없는 STT 입력에서 다수의 필드 오배정(건조함 긍정을 가려움 부정으로 덮어씀, 띄어쓰기 오류 시 제품 누락 등)이 발생했습니다.

본 작업에서는 한국어 형태소 분석기(**Kiwi**)를 도입하여 술어(용언) 중심의 **의미단위(Semantic Unit)** 분할 계층을 구축하고, 단위별 범위 한정 질문을 통해 **36개 합성 시나리오 평가에서 29건(80.6%) → 35건(97.2%)으로 정확도를 대폭 향상**시키고, **API 호출 지연(p50 0.70s → 0.40s)과 토큰 비용(약 26~33%)을 동시에 절감**했습니다.

## 2. 왜 이 작업이 필요한가요? (배경 & 문제점)

### 기존 방식의 한계 (PPO-5, PPO-16 연계 시 병목)
1. **STT 구어체에는 문장부호가 없습니다 (`PPO-5` 연계):**
   - 기존 코드는 `[,;.!?]`로만 구절을 잘랐습니다.
   - 음성 인식(STT) 결과물은 마침표나 쉼표가 거의 없어서, 2~3개의 복합 문장 전체가 1개의 거대한 구절로 묶여 버립니다.
2. **복합 증상에서 부정이 다른 증상을 오염시키는 문제:**
   - 예: `"건조하지만 가렵지는 않아"`
   - 구절이 1개로 묶여, 뒤의 `가렵지는 않아` 부정 규칙이 앞의 `건조함(긍정)`까지 읽어서 **건조함도 부정(denied)**으로 덮어써 버렸습니다 (E16 오류).
3. **띄어쓰기 오류/구어체 조사 처리 실패:**
   - `"A로션썼어"` → 공백이 없어 제품 후보 `A로션`이 아예 생성되지 않아 제품 누락 (E34 오류).
   - `"A로션은요"` → `은요`가 조사로 분리되지 않아 제품명이 `A로션은요`로 오염 (E35 오류).
4. **비용 및 지연시간 누적:**
   - 어절 단위 n-gram으로 수백 개의 후보를 만들고 Jev에게 최대 8번 순차 질문(Choice)을 던져 지연 시간(p95 ~1.2초)과 토큰 낭비가 컸습니다.

## 3. 이번에 무엇을 바꿨나요? (개선 내용)

### 1) Kiwi 형태소 분석 기반 의미단위 분할 (`segmenter.py`)
- 문장부호가 없어도 **문장 종결어미(`EF`)** 및 **대등/종속 연결어미(`EC` 중 `-지만, -는데, -고, -어서, -다가`)** 경계에서 자연스럽게 의미단위를 나눕니다.
- 단, 보조용언(`않다, 보다` 등) 앞의 연결어미는 자르지 않고 하나의 서술어로 유지합니다.
- 예: `"건조하지만 가렵지는 않아"` → Unit 1: `건조하지만` / Unit 2: `가렵지는 않아`로 완전 분리.

### 2) 형태소 단위 제품명 후보 생성
- 단일 어절 내에서 붙어있는 명사/알파벳(`A` + `로션`)은 하나의 복합명사 스팬(`A로션`)으로 온전히 유지하고, 뒤에 붙은 조사/어미(`-을`, `-썼어`, `-은요`)만 정확하게 분리합니다.
- 이에 따라 `"A로션썼어"` → `A로션` 추출, `"A로션은요"` → `A로션` 추출이 가능해졌습니다.

### 3) 형태소 표제어(Lemma) 기반 증상 매칭 및 부정 판정
- 단순 문자열 정규식이 아닌 형태소 품사와 표제어로 매칭하여, `"쓰라고 권했지만"`의 `쓰/VV`가 따가움(`쓰라리/VA`)으로 오탐되는 문제를 원천 차단했습니다 (E33 해소).
- 증상의 부정 판정을 전체 구절이 아닌 **해당 의미단위(Unit) 내부**로 한정하여 다른 증상의 긍정 판정을 덮어쓰지 않도록 격리했습니다 (E16 해소).

### 4) 담화 연결 (다문장 정정 및 강도 모름)
- `"A로션을 썼다고 했는데 잘못 말했어. 실제로는 B크림만 썼어"`처럼 여러 문장에 걸친 정정 표현을 감지하여 A=superseded, B=current로 정상 연결 (E09 해소).
- `"피부가 가려워. 얼마나 심한지는 모르겠어"`처럼 후속 문장에서 주어가 생략된 강도 모름 표현을 앞선 증상에 연결 (E20 해소).

## 4. 검증 결과 (Diverse-v1 36개 시나리오 벤치마크)

동일한 동결 평가셋(`evaluation_data/diverse-v1.json`)과 실제 Jev API 모델(`jev-1.14.0`)을 사용하여 전후를 정량 비교했습니다.

|---|---|---|---|
| **시나리오 통과율** | **29 / 36 (80.6%)** | **35 / 36 (97.2%)** | **+6건 (+16.6%p)** |
| **개별 조건 충족률** | 217 / 227 (95.6%) | **225 / 227 (99.1%)** | **+8건** |

### 유일한 미통과 1건 (E12) 설명:
- **E12**: `"A로션을 오늘 아침에는 쓰고 오늘 저녁에는 안 썼어."`
- 이는 시스템 오류가 아니라, 아침 사용(affirmed)과 저녁 미사용(denied)이라는 서로 다른 두 사용 사건이 1개 문장에 공존하는 케이스입니다.
- 평가셋 v1의 임시 기대값은 단일 필드 `conflict`로 되어 있으나, 향후 `usage_events` 2개 레코드로 분리 저장하는 것이 자연스러운 계약입니다. 팀원 검토 후 v2 기대값 설계에 반영 예정입니다.
