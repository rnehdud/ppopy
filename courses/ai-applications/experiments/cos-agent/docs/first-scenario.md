# M0 첫 시나리오와 SLM 과제 초안

상태: **검토 전 제안**, 2026-11-05. 아래 사용자, 제품, 사용법과 근거는 모두 합성 예시다. 실제 제품의 사용법이나 효능이 아니다. 사용자 확인과 사람의 정답 검토는 아직 수행하지 않았다.

## 목표와 범위

보유 제품의 확인된 사용법을 바탕으로 아침·저녁 관리 초안을 확인하고 싶은 사용자를 가정한다. 이 사례는 입력 → 조회 → 질문 → 초안 → 사용자 확인을 설명한다. 저장, 실제 앱 연동, 모델 실행, 효능 판단과 신규 제품 추천은 범위 밖이다.

## 합성 사례

- 앱 입력: 보유 확인된 제품 A (`A`, 버전 `1`)와 B (`B`, 버전 `1`). 사용자는 A를 저녁에 사용한다고 말했고 주당 횟수는 모른다. B의 현재 사용 정보는 아직 묻지 않았다. 제외 조건은 미상이다.
- 가상 조회 결과: 정확히 일치하는 A v1과 B v1에 각각 `usage-A-v1`, `usage-B-v1`이라는 합성 출처가 있다. 예시 사용법은 A는 저녁에, B는 아침 또는 저녁에 사용할 수 있다는 것이다. 조회 결과와 사용자의 현재 습관은 별개의 정보다.
- 질문 제안: “제품 B는 현재 언제 사용하시나요? 사용하지 않거나 모르시면 그렇게 답해 주세요.” 이어 제외 조건도 확인한다. 답변을 거절하면 거절 상태로 남기며, 필수 정보가 확인되지 않은 경우 초안을 보류한다.
- 가상 답변: “B는 아침에 써요. 제외하고 싶은 것은 없어요.” 이는 해당 질문에 대한 사용자 확인으로 기록한다. A의 횟수는 여전히 미상이다.
- 초안 예시: “아침: B. 저녁: A. A의 사용 횟수는 확인되지 않았습니다. 제품 사용법 확인 예시: `usage-A-v1`, `usage-B-v1`. 이 구성을 확인하거나 수정해 주세요.” 횟수는 임의로 정하지 않는다. 확인 화면은 제안이며 승인·저장은 구현되지 않았다.

## 분기 예시

| 상황 | 제안 행동 |
|---|---|
| B 사용 시간이 미상 또는 미질문 | 필요한 질문을 제시한다. 미상과 미질문은 따로 보존한다. |
| 필수 확인을 거절 | 거절로 기록하고 해당 초안 판단을 보류한다. |
| 제품 버전 미상 또는 일치하는 버전 없음 | 버전을 확인하도록 요청하거나 보류한다. 다른 버전을 대신 쓰지 않는다. |
| 사용법 출처 미확인 또는 조회 장애 | 해당 제품의 사용법을 추정하지 않고 보류와 재시도 안내를 제시한다. |
| 사용자 답변과 확인된 사용법이 충돌 | 충돌을 설명하고 판단을 보류한다. |

어떤 정보가 필수인지는 이 사례의 제안이며 실제 제품 정책으로 확정되지 않았다.

## 첫 SLM 과제 후보: 사용 답변 구조화

모델은 사용자 문장에서 사용 시간과 주당 횟수의 **후보**를 추출한다. 제품 사용법, 승인과 권한은 판단하지 않는다. 아래 값은 평가 설계 예시이며 검토된 정답이나 학습 데이터가 아니다.

| 입력 | 기대 후보 출력 | 잘못된 출력 예 |
|---|---|---|
| “저녁에 쓰는데 일주일에 몇 번인지는 몰라요.” | 시간 `pm`, 횟수 값 `null`, 횟수 상태 `unknown` | 횟수를 7로 추정 |
| “아침에 주 3번 써요.” | 시간 `am`, 횟수 값 `3`, 횟수 상태 `provided` | 시간을 `pm`으로 변경 |
| “횟수는 말하고 싶지 않아요.” | 시간 `null`, 횟수 값 `null`, 횟수 상태 `declined` | 거절을 0회 또는 미상으로 변환 |
| “아침이라고 했다가 저녁이라고 했어요.” | 시간 `null`, 시간 상태 `conflict`; 확인 질문 후보 | 마지막 값만 확정 |

문장에 없는 시간은 `null`이며 미질문인지 미상인지는 대화 문맥 없이는 확정하지 않는다. 모델 후보를 그대로 사실로 저장하지 않고 원문·문맥과 대조하고 필요하면 사용자에게 확인한다. 형식 적합성, 누락·허위 추출, 미상·거절·충돌 보존을 별도로 평가한다.

- 질문 순서, 충돌 처리 및 사용자 확인 화면의 구체적 계약.
- 첫 SLM 과제의 채택 여부, 평가 사례와 검토자. 모델·데이터·측정 결과는 아직 없다.
