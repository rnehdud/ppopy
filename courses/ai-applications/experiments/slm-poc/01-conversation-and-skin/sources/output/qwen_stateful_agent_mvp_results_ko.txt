한국어 Qwen Stateful Tool-Calling Agent MVP 구현·평가 결과
작성 기준일: 2026-11-04
상태: 데이터 정형화 및 학습 전 최소 Agent 동작 검증 완료

목적

한국어 도구 사용 데이터를 Qwen 학습 형식으로 정형화하고, 추가 학습하지 않은
Qwen2.5-3B-Instruct로 상태를 유지·수정하며 도구를 호출하는 최소 Stateful Agent를 구현·평가했습니다.

이번 단계는 "학습 전 모델로 최소 Agent를 실제로 동작시킬 수 있는가"를 확인하는 PoC입니다.
기존의 STT → Jev → 7개 Field 분류 PoC를 완료한 결과가 아닙니다.
STT, Jev API, 실제 스킨케어 KB 연동, QLoRA 학습, 제품 DB 저장, 추천 품질 검증은 미실시입니다.

핵심 결과

- 한국어 원본 15,170건 중 14,609건을 Qwen 형식으로 정형화했습니다.
- 최소 데모 1개 시나리오의 3개 턴이 모두 통과했습니다.
- 확장된 개발 테스트는 4/10개 시나리오,
  6/14개 턴이 전체 판정 조건을 통과했습니다.
- 추가 학습 없이 상태 등록 → 정정 → 정정된 상태로 도구 호출 → 결과 응답이 가능함을 확인했습니다.
- 다만 날짜 혼동, 부정문 오류, 미언급 정보 추정, 빈 응답, 출처 누락이 남았습니다.
- "최소 동작 가능"은 확인했지만, "안정적인 실사용 정확도 확보"나 "QLoRA 개선 효과"는 증명하지 않았습니다.

팀원용 한눈에 보기

한국어 텍스트 + 최신 세션 상태 + 도구 명세
                    ↓
       Qwen2.5-3B-Instruct (Q4_K_M, 추가 학습 없음)
                    ↓
      상태 갱신 / 검색을 위한 tool call 생성
                    ↓
       백엔드 검증 → Python 도구 실제 실행
                    ↓
       상태 저장 / 모의 KB 결과 반환
                    ↓
       최신 상태 + 현재 턴 도구 결과 → Qwen 응답

개발 시나리오의 정답 상태·기대 도구 ─────→ 실제 상태·호출·응답 비교

역할 구분:
- Qwen: 발화 해석, 상태 patch 및 도구·인자 선택, 도구 결과를 읽고 응답 생성.
- 백엔드: 상태 보관, 스키마 검증, 허용 도구 실행, 결과·오류·로그 반환.
- 모델 가중치에 세션 상태를 저장하는 방식이 아닙니다.
- 이전 턴 전체 이력은 로그로 보존하되, 추론에는 최신 명시 상태와 현재 턴 메시지를 전달합니다.
  따라서 상태에 기록되지 않은 장기 대화 내용을 기억하는 기능은 없습니다.

예시 입력 및 실제 성공 결과

1) 사용자: "피부가 건조해. 크림은 아침에 발랐어."
   결과: dryness / morning / product_used=yes를 기록.
   말하지 않은 severity와 symptom_onset은 unknown으로 유지.

2) 사용자: "크림을 바른 시간은 아침이 아니라 저녁이야."
   실제 Qwen이 생성한 도구 요청:

{
  "name": "update_session_state",
  "arguments": {
    "patch": {
      "usage_time": "evening"
    }
  }
}

   실행 후 실제 세션 상태:

{
  "skin_condition": [
    "dryness"
  ],
  "severity": "unknown",
  "usage_time": "evening",
  "product_used": "yes",
  "symptom_onset": "unknown"
}

3) 사용자: "현재 상태로 검색하고, 검색된 문서의 제목과 ID를 알려줘."
   결과: search_knowledge_base를 호출하고 dryness / evening을 인자로 전달.
   실제 반환된 문서 제목과 ID(FIXTURE-DRY-002)를 응답에 포함.

위 JSON은 백엔드가 관리하는 실제 5개 Field 상태입니다.
Jev 응답이나 7개 Field 전체 분류 결과가 아닙니다.
정답 라벨을 모델 입력으로 전달하거나, 정답 인자를 백엔드에서 대입하지 않았습니다.
스키마 검증은 값의 형식만 확인하며 의미가 틀린 정상 형식의 값까지 교정하지는 않습니다.

분류·상태 관리 대상 Field

Field | 후보 값 | 현재 구현 상태 및 규칙
intent | record, recommend, question, modify_routine, other | 미구현·미평가
skin_condition | dryness, breakout, redness, stinging, itching | 구현. 복수 선택. 부정된 증상 제외, 정정 시 목록 갱신
severity | mild, moderate, severe, unknown | 구현. 명시되지 않으면 unknown. 이번 기대값은 전부 unknown으로, 등급 분류 능력은 검증하지 못함
usage_time | morning, afternoon, evening, unknown | 구현. 제품 사용 시간대. 증상 발생 시점과 구분
product_used | yes, no, unknown | 구현. 사용 명시=yes, 비사용 명시=no, 미언급=기존 값 유지/초기 unknown
symptom_onset | today, yesterday, recent, unknown | 구현. 증상 시작 시점. 제품 사용일과 혼동하는 오류 관찰
routine_change_requested | true, false | 미구현·미평가

공통 누락·정정 규칙:
- 미언급은 기존 상태 유지. 초기 미언급은 unknown 또는 빈 배열([]).
- 명시적 정정은 해당 값 갱신. 다른 상태는 유지.
- 인자의 타입·enum·허용 키를 검증하며, 잘못된 요청은 실행하지 않고 오류를 반환.
- 7개 Field 전체 Exact Match는 계산하지 않았습니다. 구현된 5개 상태 항목만 비교했습니다.

도구 명세

도구 | 역할 | 구현 범위
update_session_state | patch로 세션 상태 등록·정정 | Python 메모리 상태 갱신, version과 갱신 상태 반환
search_knowledge_base | 모델이 선택한 조건으로 모의 문서 조회 | 합성 fixture의 skin_condition 태그로 문서 선택

모의 검색에서 query와 usage_time은 수신·기록되지만, 실제 문서 선택은 증상 태그를 기준으로 합니다.
벡터 검색, 의미 검색, 실제 RAG 또는 기존 스킨케어 KB의 검색 품질을 구현·검증한 것은 아닙니다.
한 번에 하나의 도구 호출을 처리하며, 알 수 없는 도구·잘못된 인자·중복 호출 등을 차단합니다.
도구 오류와 반복 실행 상한을 로그에 기록합니다.

학습에 필요한 assistant-only loss mask 및 Trainer 구현은 이번 범위에 포함하지 않았습니다.

평가 설계 및 실행 결과

실험 | 입력 | 목적 | 결과
A0 | 단순한 한국어 3턴 → Qwen Agent → 모의 도구 | 상태 등록·정정·조회·응답의 최소 동작 | 1/1개 시나리오, 3/3턴 전체 조건 통과
A1 | 한국어 개발 시나리오 → Qwen Agent → 모의 도구 | 부정·시간·미언급·정정·오류·출처 등 점검 | 4/10개 시나리오, 6/14턴 전체 조건 통과
B | 음성 → STT → Agent 또는 Jev | 음성 포함 End-to-End 평가 | 미실시
C | 음성 → STT | 전사 품질 | 미실시
D | 한국어 공개 데이터 → 정형화 → Qwen 템플릿 | 학습 후보 데이터의 구조 적합성 | 14,609건 채택, 561건 제외

A0와 A1은 별도 개발용 평가입니다. 합쳐서 일반화 성능으로 제시하지 않습니다.
프롬프트·구조 조정에 사용했으므로 고정 독립 테스트나 학습 개선 효과를 나타내는 결과가 아닙니다.
과거 pilot/baseline 기록은 조건이 달라 단순 비교하지 않고, 아래 최종 기록을 기준으로 합니다.

A1 상태 Field별 결과 (14턴, 도구 실행 후 상태 기준)

Field | 정답 턴/전체 턴 | Accuracy
skin_condition | 13/14 | 92.86%
severity | 14/14 | 100.00%
usage_time | 14/14 | 100.00%
product_used | 14/14 | 100.00%
symptom_onset | 10/14 | 71.43%

- skin_condition Accuracy는 증상 목록 전체가 일치한 턴 비율입니다.
- skin_condition micro Precision: 0.9231
- skin_condition micro Recall: 0.9231
- skin_condition micro F1: 0.9231
- 집계값: TP=12, FP=1, FN=1
- 5개 상태 Field Exact Match: 10/14턴 (71.43%)
- 7개 Field Exact Match: 미측정 (2개 Field 미구현)
- 시나리오 전체 통과: 4/10 (40.00%)
- 턴의 모든 해당 조건 통과: 6/14 (42.86%)
- 상태가 맞아도 도구 미호출·빈 응답·출처 누락 등이 있으면 턴/시나리오는 실패 처리했습니다.
- severity 기대값은 전부 unknown입니다. 100%가 심각도 분류 전반의 우수함을 뜻하지 않습니다.
- 100%인 다른 항목도 14개 개발 턴에서의 관측값일 뿐 일반 성능을 단정하지 않습니다.

응답 시간 및 비용

- A1에서 최종 응답까지 완료한 12개 턴의 평균: 1.851초
- 동일한 완료 턴의 P95: 2.261초 (nearest-rank)
- 상태·도구 루프를 포함한 턴 처리 시간입니다.
- 실패한 2개 턴은 위 완료 응답 지연시간 통계에서 제외했습니다.
  따라서 전체 요청 기준 SLA나 전체 End-to-End P95가 아닙니다.
- 로컬 추론이므로 이번 실험에서는 Jev·STT·외부 LLM API를 호출하지 않았습니다.
- 전력·GPU 감가·모델 다운로드 등의 총비용은 산정하지 않았습니다. 무료 운영을 의미하지 않습니다.
- STT CER/WER, Jev intent Accuracy, Jev Field별 Accuracy는 미측정입니다.
- 미언급/부정 오분류의 독립된 비율 지표는 아직 산출하지 않았으며 사례로 기록했습니다.

대표 실패 사례 및 해석

1. 증상 발생일과 제품 사용일 혼동
   "오늘 볼이 따가워. 어젯밤에 로션을 발랐어."에서 증상 발생일을 제품 사용일과 혼동.
   형식은 유효하여 스키마 검증만으로는 교정되지 않았습니다.

2. 부정문에서 증상 오등록
   "가렵지는 않고 따가워."를 포함한 입력에서 기대한 증상 목록과 다른 값이 기록되었습니다.
   부정과 실제 양성 증상을 분리하는 의미 이해가 불안정합니다.

3. 미언급 증상 발생일을 추정
   제품을 어젯밤에 사용했다는 정보만으로 증상 시작도 yesterday로 기록하는 사례가 있었습니다.
   이후 다른 상태를 정정해도 잘못된 발생일이 유지되는 문제가 있습니다.

4. 빈 모델 응답
   일부 검색 요청이나 모호한 요청에서 도구 호출도 설명도 없는 빈 응답이 발생했습니다.
   백엔드는 이를 성공으로 위장하지 않고 empty_model_response로 기록했습니다.

5. 검색 결과를 받은 뒤 출처 누락
   동일한 요청에서 초기 상태가 다르면 올바르게 다른 검색 인자를 만들 수 있었습니다.
   하지만 실제 반환 문서 ID를 답변에 포함하지 않아 전체 판정은 실패했습니다.

6. 상태·검색 결과 밖의 자유문장 추가
   일부 응답에서 제품이 증상을 유발했다는 식의 근거 없는 인과 표현이 관찰되었습니다.
   이번 PoC는 자유 응답의 의료적 타당성을 보장하지 않습니다.
