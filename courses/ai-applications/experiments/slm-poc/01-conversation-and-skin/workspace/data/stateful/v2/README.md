# 韓国語Stateful Tool-Use合成データ v2

学習前に固定した、状態更新とツール使用の制御実験用データです。
実ユーザーの肌情報・音声・医療的正解を収集したデータではありません。

| split | シナリオ | ユーザーターン | 重複除去後の判断例 |
|---|---:|---:|---:|
| train | 209 | 314 | 529 |
| validation | 30 | 44 | 80 |
| holdout | 59 | 84 | 143 |

各splitは異なる表現テンプレート群から生成し、ユーザー発話の完全一致がsplitを跨がないことを確認しています。
意味カテゴリは共通です。テンプレート外の自然な韓国語全般に対する汎化性能を保証しません。

## 内容

症状の登録、製品使用日と症状開始日の区別、使用時点の訂正、開始日の訂正、
否定、明示的非使用、未言及、症状の取消し、状態を使った検索、検索障害、挨拶、曖昧な依頼の12カテゴリです。

`*.cases.json`は初期状態・発話・期待状態・正解の行動を持つシナリオです。
`*.sft.jsonl`は各判断時点の`messages + tools`です。最後のassistantメッセージだけを教師対象にします。
正解の行動はパラメーターから明示的に設計し、評価対象モデルやテキスト抽出器の予測を正解としていません。

教師軌跡は、実装済み`Session`と2つのPythonツールを実行して、各ターン後の状態を検証しています。
これは構造・実行の検証であり、別の人間による全件の言語・意味レビューではありません。
生成後のレビューで、使用時点を持つ初期状態と使用有無の整合、いくつかの語形を修正しました。
その前のv1は履歴として残し、今回の学習・比較ではv2のみを使います。

## 固定のルール

`manifest.json`に全データファイルのSHA256を記録しています。
学習開始前と比較終了後に同一性を検証します。holdoutはプロンプト調整・学習・checkpoint選択には使いません。
holdoutのSFT形式も参照・監査用に置いていますが、学習処理はtrainだけを読みます。
検証損失の計算にはvalidationだけを使用します。

`scripts/build_stateful_corpus.py`は既存の同一バージョンを上書きしません。
追加・修正する場合は別バージョンを作り、その後に比較を開始してください。

## モデルに渡す情報

モデルの入力は最新の明示状態、現在ターンの発話・実行済みツール結果、ツール仕様です。
期待値、正解行動、次ターンの情報は評価中のモデルへ渡しません。
KB検索は合成文書のタグ一致であり、実KB・RAG・医学的妥当性を検証するものではありません。

## マスクと学習例

`scripts/prepare_stateful_training.py`は公式Qwenテンプレートでprefixと教師completionを別々に検証します。
prefixのトークンが完全に一致することを確認し、最後のassistantより前を`-100`でマスクします。
ツール結果やユーザーの文章を出力として学習させません。長い例も途中で切り捨てません。
トークン列とマスクの確認例は`data/processed/stateful_v2/`へ出力します。

v2は最初の100シナリオを含む全シナリオの実行検証を済ませています。
今回の小規模学習で使うのはこの中から固定seedで選んだ100判断例です。
これに、既に整形済みの公開韓国語ツールデータのtrainから20判断例を混合する設定です。
公開評価セットFunctionChat-Benchと、そのほかのtestデータは混ぜません。
